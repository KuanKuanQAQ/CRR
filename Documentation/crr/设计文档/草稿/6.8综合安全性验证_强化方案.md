## 1. 诊断：现在 §6.8 弱在哪

当前 §6.8 有三处结构性问题，导致"论证不够有力"：

1. **向量是抽象的，攻击是具体的。** 表 6-13 的每一行写的是 V1/V2/V3/V4-A/V4-B，读者（尤其是有安全背景的评委）会问："你说的 V1 到底对应现实里哪一个漏洞的哪一步？"向量矩阵证明的是"机制与机制的接口自洽"，没有证明"机制与**现实攻击**接口自洽"。
2. **没有建立"普适性"的论证。** 现在 §6.8 只能说明"这条假设的链被挡住了"，不能说明"别的漏洞、未来的漏洞也被挡住"。缺一条从"单条链"推广到"这一类链"的归纳论证。
3. **缺一个诚实的反例面。** 真实的现代内核提权利用里，有很大一部分（Dirty Pipe、CVE-2024-1086 等）是**纯数据攻击**，根本不需要代码地址。不主动点破这一点，等于把软肋留给答辩现场。

## 2. 核心论证策略：从"CVE 清单"到"攻击阶段覆盖"

**"I-KASLR 能挡住哪些 CVE"是错误的问题**，原因有二：一个 CVE 可以有多种利用（数据型/控制流型），"挡住 CVE-X"无法严格成立；而且挡住十个已知 CVE 也不能说明能挡住第十一个。

**正确的问题是："I-KASLR 能挡住的**攻击阶段**，被多少条真实利用链**必然经过**。"** 论证分四步：

1. **把内核提权利用拆成阶段。** 任何控制流劫持型利用，无论入口缺陷是 UAF、OOB、类型混淆还是竞态，都必须在某一时刻（a）**获知一个代码地址**（ROP/JOP/COOP 要把 gadget 地址写进被劫持的代码指针），并在（b）**把这个地址写进一个代码指针/返回地址**。
2. **步骤（a）只有三条路**：读代码（V1）、执行试探（V2）、读代码索引（V3）。这三者分别被第 4 章（V1/V2）与第 3 章（V3 结构消除）覆盖。
3. **步骤（b）若目标是区域内代码**，其地址在"泄露→使用"之间已经失效（I2 时效性，第 4 章触发 + 第 3 章快速随机化）；**若目标是区域外代码**，落在非随机化区域，其跨区域转移受第 5 章分区验证约束（I3）。
4. 因此：**防御对象是"阶段"而非"缺陷"**。任何以"获知代码地址 + 覆写代码指针"为必要中间步骤的利用——包括基于尚未被发现缺陷的未来利用——其必要中间步骤都落在 I-KASLR 的覆盖内。**普适性由此成立，且不依赖任何具体 CVE 的先验知识。**

仅剩的两条逃逸路径是（i）数据导向攻击（不改变控制流）、（ii）微架构侧信道（不产生可观测事件），二者均已在第 2.6.4 节显式排除。**因此这一归纳论证是封闭的**：在威胁模型划定的边界内，"需要代码地址"与"被 I-KASLR 覆盖"互为充要。

## 3. 为什么必须把"数据类利用"写进去（而不是藏起来）

公开利用链的现实是：2016–2024 年大量高影响内核提权利用**最终一步都是覆写 `modprobe_path` 或 `cred` 这类数据符号**，而不是 ROP。典型如：

- **CVE-2024-1086**（nf_tables UAF）：经"脏页表"获得**任意物理读写**，扫描物理内存定位 `modprobe_path`，全程不需要任何代码地址，KASLR 对其完全无效。
- **CVE-2022-0847（Dirty Pipe）**、**CVE-2021-22555**、**CVE-2022-0185**：最终都是覆写数据。

**主动写进 §6.8 反而更强**，理由有三：

1. 它说明本文的边界判断是**清醒的**，与第 2.6.4 节"纯数据攻击"排除项一致——评审看到"边界已知且被显式声明"比看到"作者似乎没意识到"好得多；
2. 它把**论证的分量转移到"阶段覆盖"上**：I-KASLR 不声称按 CVE 计数兜底，而是声称按"控制流劫持这一必要阶段"兜底，这条论证不会因为"数据类 CVE 更多"而被削弱；
3. 它顺带给出**防御深度的落点**：数据类利用需要数据流完整性/内存安全强制等正交手段，本文机制可与之叠加（第 1.1.2 节已声明）。

## 6.8 综合安全性验证

### 6.8.1 论证策略：以真实攻击链为对象、以攻击阶段为判据

本节验证三项机制对完整攻击路径的协同拦截。与第 4、5 章机制级实验的区别在于**验证的粒度**：前两章验证单个机制对单类行为的响应，本节验证攻击者依次尝试泄露、定位、构造、劫持、提权时，每一步分别在哪一档配置下被哪个机制挡住。**只有在完整链条上才能看出机制之间是否存在缝隙**——单独测试各自通过，并不排除攻击者绕开其中一项、从另外两项之间穿过。

在进入拦截矩阵之前，本节先处理一个方法学问题：**用什么对象来验证，结论才算有力。** 本文不以"复现某个具体 CVE"作为验证对象，理由有二。其一，一个 CVE 往往对应多种利用方式，有些需要代码地址、有些不需要，"挡住 CVE-X"这一命题在字面上无法严格成立。其二，即便挡住十个已知 CVE，也不能推出能挡住第十一个——逐条复现提供的是**枚举证据**，而防御机制需要的是一句**普遍命题**。

因此本节改用**公开利用链的阶段性拆解**作为验证对象。本文不重新实现这些利用（攻击载体属两用代码，已在实现阶段永久移除），而是以公开 writeup 中记录的利用步骤为材料，把它们拆解为若干通用阶段，再映射到第 2.6.2 节的四类攻击向量。这一做法的结论形态是：**I-KASLR 挡住的是"获知代码地址、覆写代码指针"这一攻击阶段本身，而非任何具体缺陷**；因而任何必须经过该阶段的利用——无论其入口是释放后使用、越界写、类型混淆还是竞态——都落在覆盖之内。这是第 6.8.6 节归纳论证的实证基础。

### 6.8.2 真实 CVE 利用链的阶段拆解与映射

表 6-13 把若干有公开完整利用链分析的内核提权漏洞按阶段拆开。拆解的对象是公开 writeup 中记录的**利用步骤**，而非漏洞本身；每行的"代码地址步骤"一栏标出该利用是否**必然**经过"获知代码地址"或"覆写代码指针"这一阶段——这是判断 I-KASLR 是否覆盖的判据。

**表 6-13　真实内核提权 CVE 利用链的阶段拆解与 I-KASLR 覆盖**

| CVE | 缺陷类型（子系统） | 公开利用链的阶段分解 | 是否必经代码地址步骤 | 落入的攻击向量 | I-KASLR 阻断点 |
| --- | --- | --- | :-: | --- | --- |

| CVE-2021-22555 | 堆 OOB 写（netfilter） | OOB 写 → UAF → 任意读写 → 覆写 `modprobe_path` | 否 | —（纯数据攻击） | 超出范围 |

表 6-13 上、下两半各自对应一类利用，二者的分界正是"是否必经代码地址步骤"。

**上半部分是 I-KASLR 的防御对象。** 这三条利用链的入口缺陷各不相同——引用计数 UAF、越界写、双重释放——但都收敛到同一条后继路径：先获知一个代码地址、再把它写进代码指针、最后进入 ROP。I-KASLR 的拦截点落在这些**共有**的后继阶段上，而非各自的入口缺陷上。这就是"防御阶段而非防御缺陷"的实证形态：入口缺陷千差万别，必经阶段只有几条。

**下半部分不是本文的防御对象，主动列出是为了把边界画清楚。** CVE-2024-1086 尤其值得说明：其利用经"脏页表"获得任意**物理**读写，直接扫描物理内存定位数据符号 `modprobe_path`，全程不需要任何代码地址，因而 KASLR 与本文机制对它都不构成障碍。这与第 2.6.4 节"纯数据攻击"排除项完全一致——防御此类攻击需要数据流完整性或内存安全强制等正交手段。**把这一类列出，恰是本节论证的诚实性所在**：它说明本文不按 CVE 计数兜底，而是按"控制流劫持这一必要阶段"兜底，这一命题不会因为数据类 CVE 数量更多而被削弱。

表 6-13 给出的是**现实利用与攻击向量的对应关系**，下面把它落回四档配置，看每一步在哪一档被哪个机制挡住。

表 6-14 的价值在于**逐列展示每个机制各自拦住了哪一步**，而不只给出"攻击失败"这一个结论。三项机制的拦截位置互不重叠：第 3 章在 +R 档消除了 V3，第 4 章在 +RD 档检测 V1 与 V2，第 5 章在 +RDP 档拒绝 V4 的两种形态。**没有任何一档独自拦住全部步骤**，这正是三项机制协同而非冗余的证据。结合表 6-13 可以进一步读出：上半部分的每一条真实利用链，都命中表 6-14 中至少一行"被拦截"的步骤，且命中的是同一批步骤——这印证了第 6.8.1 节"防御阶段"的判断。

矩阵中有一行需要如实说明：在 +RD 档下，V4-A 与 V4-B 仍然成功，攻击最终失败是因为攻击者在此之前已被检测并触发随机化，其掌握的地址随即失效。也就是说，**+RD 档拦住攻击靠的是时效性而非完整性**；只有到 +RDP 档，跨区域转移本身才被拒绝。这一区别在讨论机制不可或缺性时需要交代。

**这一口径也顺带回应了"数据类 CVE"的质疑。** 表 6-13 下半部分的利用不需要 gadget，表 6-15 因此对它们不构成任何约束——这与第 2.6.4 节的排除一致，反过来说明：gadget 数量这一指标只对"需要 gadget 的利用"有意义，而对"不需要 gadget 的利用"不应越界声称有效。

### 6.8.5 泄露地址的有效期

第 2.2.3 节已说明，本文机制不减少映像中 gadget 的数量，改变的是它们的地址在运行时是否稳定。因此安全性评估的核心指标是**地址的有效期**，即一个被泄露的代码地址从泄露到失效之间的时长。

| Base | 永久有效 | — | — | — |
| +R（固定间隔） | 10.2 ms | 19.1 ms | 19.8 ms | 20.0 ms |
| +RD（按需，正常负载） | 2,280 ms | 3,410 ms | 3,900 ms | 4,200 ms |
| **+RD（按需，攻击负载）** | **0.021 ms** | **0.049 ms** | **0.092 ms** | **0.14 ms** |
| +RDP（攻击负载） | 0.019 ms | 0.046 ms | 0.088 ms | 0.13 ms |

**图 6-5　泄露地址有效期的累积分布**（阴影带为第 1.1.5 节引用的随机化间隔上界）

表 6-16 与图 6-5 给出本文按需触发策略的核心价值，它体现为一种**非对称性**：在正常负载下，随机化稀疏发生，地址有效期的中位为 2,280 ms，接近第 1.1.5 节引用的间隔上界，系统几乎不为随机化付出代价；而一旦检测到探测行为，有效期立即降至 0.021 ms，比上界低四个数量级。

**固定间隔方案无法做到这种非对称。** +R 一档在正常负载下也维持 10.2 ms 的有效期，代价是持续不断地随机化；若把间隔放宽以省下开销，则攻击发生时的有效期同样被放宽。按需触发使"平时省、战时快"成为可能，这是第 4 章存在的根本理由。

回到表 6-13 上半部分的三条利用链：它们"获知代码地址"之后到"把地址写进代码指针"之间，必然还有一段构造与布置的时间（堆喷、布局调整、触发写原语）。表 6-16 的攻击负载有效期（中位 0.021 ms）比这段构造时间低若干数量级，因此即便攻击者成功泄露了一个区域内地址，它也会在攻击者来得及使用之前失效。**这是"阶段覆盖"落到时间轴上的形态**：I-KASLR 不阻止泄露发生，但使泄露的结果在"泄露"与"使用"两个阶段之间作废。

### 6.8.6 普适性：从"这组 CVE"到"这一类利用"的归纳

表 6-13 是归纳论证的实证前提，本小节把它推广为一句普遍命题。

**归纳前提。** 表 6-13 上半部分显示，三条入口缺陷完全不同的真实利用链，其后继阶段收敛到同一集合：获知代码地址（V1/V2/V3 之一）、覆写代码指针（V4-A 或 V4-B）、进入 ROP。这个收敛不是巧合，而是控制流劫持的定义使然：ROP/JOP/COOP 的全部前提就是"攻击者知道 gadget 的地址、并能把该地址写进一个将被执行的代码指针"。

**归纳步骤。** 设未来出现一个新的内核缺陷 D，其利用若属于控制流劫持类，则必须满足上述两个前提条件之一或全部：
- 若需**获知**代码地址：在 I-KASLR 下，内存中不存在指向随机化区域内部的索引（第 3 章，V3 消除），直接读代码与执行试探会触发检测（第 4 章，V1/V2），故获知只能以被检测为代价完成；
- 若需**使用**代码地址：区域内代码的地址在泄露与使用之间已经失效（第 4 章触发 + 第 3 章 O(1) 随机化，I2），区域外代码的跨区域转移受分区验证约束（第 5 章，I3）。

**结论。** 在威胁模型（第 2.6 节）划定的边界内，"控制流劫持型利用必然经过 I-KASLR 的覆盖阶段"这一命题对**所有**此类利用成立，与缺陷 D 的类型、位置、发现时间无关。普适性由此成立，且**不依赖任何对 D 的先验知识**——这是本文防御区别于"为已知漏洞打补丁"的本质所在。

**逃逸路径的封闭性。** 使上述命题不成立的仅有两条路径：数据导向攻击（不改变控制流，因而无需代码地址）、微架构侧信道（不产生本文可观测的事件，因而绕过检测）。二者均已列入第 2.6.4 节的排除项，并分别需要数据流完整性/内存安全强制、以及针对侧信道的正交防御来应对。**在本文声明的防御范围内，上述归纳是封闭的**——这一点应当连同排除项一起，作为本章安全性结论的一部分如实呈现。

## 5. 第 3/4/5 章安全性分析的补充段落

> 三处均插入到各章"安全性分析"节末尾、""讨论"节之前。作用是让每章的安全性论证都**落到至少一条真实 CVE 的利用链上**，与第 6.8 节的表 6-13 互相引用。文案已按各章术语对齐。

### 5.1 插入第 3 章（§3.7 末尾，新增 §3.7.5）

**§3.7.5 在真实攻击链中的位置。** 本章对 V3 的消除可以放到真实利用链中理解。第 6.8.2 节表 6-13 上半部分的三条利用链（CVE-2016-0728、CVE-2017-1000112、CVE-2022-2588）都以"获知一个代码地址"为必经中间步骤；在基线内核中，攻击者可以通过读取栈上的返回地址、结构体中的函数指针、跳转表项来获知该地址——这正是 V3。经本章的位置无关代码与跳板改造后，内存中不再存在指向随机化区域内部的索引：函数指针的值恒为位置固定的跳板地址，栈上返回地址指向的旧位置由陷阱镜像接管（第 3.4.7 节）。**因此表 6-13 中"读索引推断布局"这一列，在 +R 档即从攻击路径上整体消失**，攻击者即便完整读取全部数据段与栈，得到的也只是跳板地址。这是本章对不变式 I1 的结构性贡献，也是"防御阶段而非防御缺陷"在 V3 上的体现——它不针对任何具体 CVE 的缺陷，而针对一切"经索引获知代码地址"的共性步骤。

### 5.2 插入第 4 章（§4.7 末尾，新增 §4.7.4）

**§4.7.4 在真实攻击链中的位置。** 本章对 V1 与 V2 的检测同样对应真实利用链中的共性步骤。JIT-ROP 型利用（第 2.1.4 节）以"读代码页收集 gadget"为起点，这对应 V1；向猜测地址发起转移、以异常与否判断地址有效，这对应 V2。第 6.8.2 节表 6-13 中"覆写函数指针 → ROP"的利用链，其前置阶段必然是二者之一：要么先读代码拿到 gadget 地址，要么先试探确认地址有效。本章的检测源一（代码读取）与检测源二（执行试探）分别在 +RD 档把这两个前置阶段变为可观测事件，再经控制流审计筛掉合法读取，触发一次针对性的重随机化。**其效果在第 6.8.5 节表 6-16 中表现为攻击负载下地址有效期降至 0.021 ms**：攻击者即便成功读到地址，也会在"泄露"与"使用"之间失去它。需要注意的是，表 6-13 下半部分的数据类利用（CVE-2024-1086、Dirty Pipe 等）不经 V1/V2，因而本章对它们不构成约束——这一边界与第 2.6.4 节一致，不应越界声称。

### 5.3 插入第 5 章（§5.7 末尾，新增 §5.7.4）

**§5.7.4 在真实攻击链中的位置。** 本章对 V4 的约束对应真实利用链中的"覆写代码指针"阶段。第 6.8.2 节表 6-13 上半部分的三条利用链，最终一步都是把一个攻击者选定的地址写进一个将被执行的代码指针——CVE-2016-0728 覆写的是 `key->revoke` 函数指针，CVE-2017-1000112 与 CVE-2022-2588 覆写的是内核对象中的函数指针或跳转目标。这些被覆写的调用点若位于非随机化区域，其间接转移由本章的分区 PA 验证约束：攻击者写进去的目标既无法通过调用点唯一上下文的认证，也未必落在白名单内，因而在 `fixed_out` 处被拒绝。**这与表 6-14 中 V4-A、V4-B 两行在 +RDP 档被拒绝对应**。需要再次强调边界：本章约束的是**跨区域与控制流相关**的间接转移，纯数据覆写（如直接改写 `cred` 或 `modprobe_path`，见表 6-13 下半部分）不经过任何控制流转移，不在本章约束范围内——这一边界与第 1.1.2 节、第 2.6.4 节一致。

## 8. 一句话总结（回复评审时的标准答案）

> "I-KASLR 不是针对某个 CVE 的补丁，它针对的是所有控制流劫持型利用都无法跳过的那个阶段——先获知代码地址、再覆写代码指针。我们用公开利用链证明：无论入口是 UAF、越界写还是竞态，真实利用都会收敛到这几个阶段；而数据导向攻击不经过这些阶段，我们明确不声称防御。普适性来自'阶段'的封闭性，而不是来自'CVE 清单'的长度。"
