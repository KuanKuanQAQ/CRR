# 论文插图绘图指导

本文档从两批参考图中提炼出统一的视觉语言：一批是王喆博士论文的插图（`截屏*.png` 中题注为「图 x.x / Figure x.x」的），另一批是本文作者自己已画好的插图（题注为「图 3 / 图 4 / 图 7 …」的，即 `截屏2026-09-09 08.25.07` 起的若干张，以及 `design.png`、`控制流迁移.png`）。

**以本文作者自己的那批为主基调**：它们比王喆的更干净——去掉了截图、图标、渐变、粗黑填充，改用细线框、浅色区域填充、等宽字体的代码块。本文全部新图都应向这个基调靠拢。

全部插图最终以 SVG 绘制、转 PDF 后 `\includegraphics` 进 LaTeX，始终显示在白纸上，因此**不需要暗色主题**，单一浅色配色即可。

---

## 一、统一的视觉规范（三种风格共用）

### 1. 配色

分三组：**区域色**（表示地址空间中的三类区域，是全文固定约定，不可随意改）、**语义色**（表示元素的角色）、**中性色**（框线、文字、背景）。

**区域色（固定约定，来自 `控制流迁移.png`）**

| 区域 | 边框 | 填充 | 含义 |
| --- | --- | --- | --- |
| 非随机化区域 | `#D98A80` | `#FBEDEB` | 位置固定、布局已知 |
| 跳板区域 | `#5FB0C4` | `#E6F4F7` | 视觉枢纽，边框可加粗到 2–2.4 |
| 随机化区域 | `#7FB86A` | `#EDF6E7` | 位置持续变化 |
| 内核堆 / 外部数据 | `#9AA0A6` | `#FFFFFF` | 攻击者已占据的立足点 |

**只要图里出现「三条区域带」，一律用这套颜色**，读者跨图就能对上。第 3、4、5 章的架构图应共用同一套区域带骨架，看起来像同一张图的三次叠加。

**语义色**

| 角色 | 边框 | 填充 | 用于 |
| --- | --- | --- | --- |
| 高亮数据 | `#C9A94E` | `#F3E7C9` | 米色。关键数据块：`target_addr`、PA Code、陷阱区域、被泄露的地址 |
| 硬件 / 系统部件 | `#9AA0A6` | `#E2E2E2` | 浅灰。CPU、EPT、观察点、QARMA 等 |
| 溢出 / 危险 | `#A0342A` | `#FFFFFF` | 深红边框。堆栈溢出复写区域、被攻击者控制的数据 |
| 强调 / 触发 / 攻破 | `#8C3A2B` 线与字 | — | 砖红。攻击箭头、「触发随机化」、阶段「被攻破」 |
| 本文机制强调 | `#2F4B7C` 线与字 | `#DCE6F4` 填充 | 靛蓝。仅用于突出「本文的做法」，用量要省 |

**代码 / 助记符**

- 等宽字体正文：`#1C2126`
- 指令助记符（`LDR` `AUTIA` `INC_REF_CNT` `PACIA`）：紫色 `#9B3FA8`。这是本文作者图 22、design.png 的固定用法。
- 立即数、地址、寄存器名：保持黑色。

**中性色**：文字 `#1C2126`，次要文字 `#6B7280`，框线 `#CFD4D9`（浅）/`#4A5560`（普通节点），背景 `#FFFFFF`。

### 2. 字体

- 中文标签与说明：`PingFang SC, Hiragino Sans GB, Microsoft YaHei, sans-serif`
- 代码 / 汇编 / 十六进制 / 地址：等宽 `"SF Mono", "Menlo", "Consolas", ui-monospace, monospace`
- 图题不画进 SVG，由 LaTeX 的 `\caption` 生成，因此 SVG 里**不含**「图 x-x」字样。

字号：节点主标题 13–15，节点副文字 11–12，代码 12–13，图例 11.5，角标说明 11。

### 3. 箭头与连线（固定约定，来自各图的 Note）

| 线型 | 含义 |
| --- | --- |
| 实线 + 实心箭头 | 控制流 |
| 虚线 + 实心箭头 | 数据流 |
| 砖红实线 + 箭头 | 攻击行为 / 触发 / 打破 |
| 砖红虚线 | 章与章之间的依赖 |

线宽：主流程 1.3–1.4，次要 1。箭头统一用一个小三角 `marker`（见文末代码骨架）。

### 4. 步骤编号

用**深色实心小圆 + 白色粗体数字**（王喆的 ❶❷ 与本文作者图 7 的 ①②③ 都是这种）。圆填充 `#2F4B7C` 或 `#333`，半径 9。表示一条流程的先后顺序时用它，静态结构图不用。

### 5. 图例

放在图的右侧一列或底部一行，与正文同字号。**凡是用到线型约定或区域色的图都要带图例**，这是两批参考图的共同做法。

## 二、三种风格及其适用范围

### 风格 A — 内存布局与数据结构图

**何时用**：要展示地址空间里的东西——内存区域怎么分布、代码怎么重定向、指针指向哪里、栈帧长什么样、一段汇编转换前后的对照。

**构成元素**
- 高瘦的「容器」矩形代表一块内存（栈、堆、代码段），内部堆叠小格代表条目 / 表项 / 指令。
- 地址标签（`addr1:`、`0xbf1d`）写在容器**左侧外面**。
- 代码 / 十六进制用等宽字体，助记符用紫色。
- 区域用区域色填充；关键数据块用米色高亮。
- 实线=控制流、虚线=数据流，穿行于容器之间。
- 右上角或独立一框放「Note / 图例」。

**代表参考图**：`design.png`、`控制流迁移.png`、图 3（ROP 流程）、图 4（代码索引种类）、图 12（PIC）、图 22（PA 原理）、王喆图 2.7 / 5.3 / 5.5。以及本文已定稿的 `内存错误利用模型.svg`。

**本文用它画**：第 3 章跳板控制流重定向、函数级 PIC、精确暂停时序中的内存态；第 4 章被探测函数重映射、只执行内存的多重映射绕过、EPT 与伙伴系统；第 5 章 PA 原理、分区验证的内存视角、高扇入识别。

### 风格 B — 系统架构与流水线图

**何时用**：要展示整个系统由哪些模块构成、编译期到运行期的数据怎么流、各机制在系统里的位置。

**构成元素**
- 横向的「阶段带」，左侧写阶段名（`编译期:`、`运行期:`、`随机化阶段:`），带与带之间用一条细灰线分隔（本文作者图 7 的做法）。
- 五边形 / 雪佛龙块箭头承载流程步骤，箭身里可写一句话，配圆圈步骤号。
- 模块框用浅灰填充；被保护 / 随机化的部分套区域色。
- 右侧一列图例。

**代表参考图**：本文作者图 7（信息泄露检测框架，**首选范本**）、王喆图 5.1 / 6.4（架构）、图 5.6（运行时重随机化流程）。

**本文用它画**：图 1-2 I-KASLR 系统总览、第 3/4/5 章各自的机制架构图、第 6 章原型构成图。

### 风格 C — 概念关系与时序图

**何时用**：要展示随时间的演进、若干概念之间的对应关系、或一条时间轴上事件的先后。信息偏「抽象关系」而非「内存实体」。

**构成元素**
- 一条横向时间轴，或自左向右 / 自上而下的阶段推进。
- 简单矩形沿轴排列，灰色填充的长条表示时长 / 区间。
- 以灰阶为主，只留一个强调色（通常砖红表示攻击 / 打破，靛蓝表示本文）。
- 层与层之间用连线表达对应关系，连线端点的形状可编码语义（实心方块=结构消除，空心圆=运行时检测）。

**代表参考图**：图 15（随机化推迟时序）、王喆图 2.6（记录 / 回放两阶段）、图 4.3（三种插桩对照）。

**本文用它画**：图 2-1 内核随机化三阶段、图 2-5 攻击向量与不变式对应、第 4 章有效随机化时间窗口、随机化频率敏感性。

## 三、可复用的 SVG 骨架

所有图共用同一段 `<defs>` 与 `<style>` 前缀，改 class 即可。坐标用整数、留边距，容器用 `rect` + `text`，连线用 `polyline`。

```xml
<defs>
  <marker id="ah" viewBox="0 0 8 8" refX="7" refY="4" markerWidth="7" markerHeight="7" orient="auto">
    <path d="M0,0 L8,4 L0,8 z" fill="#3d444c"/></marker>
  <marker id="ah-r" viewBox="0 0 8 8" refX="7" refY="4" markerWidth="7" markerHeight="7" orient="auto">
    <path d="M0,0 L8,4 L0,8 z" fill="#8C3A2B"/></marker>
</defs>
<style>
  .code   { font-family:"SF Mono",Menlo,Consolas,ui-monospace,monospace; }
  .mn     { fill:#9B3FA8; }                 /* 指令助记符 */
  .zone-n { fill:#FBEDEB; stroke:#D98A80; } /* 非随机化 */
  .zone-t { fill:#E6F4F7; stroke:#5FB0C4; stroke-width:2.2; } /* 跳板 */
  .zone-r { fill:#EDF6E7; stroke:#7FB86A; } /* 随机化 */
  .data   { fill:#F3E7C9; stroke:#C9A94E; } /* 高亮数据 */
  .hw     { fill:#E2E2E2; stroke:#9AA0A6; } /* 硬件 */
  .cf     { fill:none; stroke:#3d444c; stroke-width:1.3; marker-end:url(#ah); }         /* 控制流 */
  .df     { fill:none; stroke:#3d444c; stroke-width:1.2; stroke-dasharray:5 3; marker-end:url(#ah); } /* 数据流 */
  .atk    { fill:none; stroke:#8C3A2B; stroke-width:1.4; marker-end:url(#ah-r); }        /* 攻击/触发 */
</style>
```

步骤编号圆：

```xml
<circle cx="X" cy="Y" r="9" fill="#2F4B7C"/>
<text x="X" y="Y+4" text-anchor="middle" fill="#fff" font-weight="600" font-size="12">1</text>
```

## 四、几条硬约束

1. **区域色是全文约定**，不随图变。三条带在哪张图里都是粉 / 青 / 绿。
2. **不要画图标**（CPU 芯片、齿轮、放大镜、小人）。参考图里王喆用了、本文作者没用；本文一律不用，用文字框代替。
3. **SVG 里不写图题**，图题交给 LaTeX。
4. **等宽字体只给代码**，中文标签用 sans。
5. 每张带线型约定或区域色的图都要有图例。
6. 版面留白：节点之间留够间距，宁可图大一点也不要挤。参考本文作者图 7 的疏密。
