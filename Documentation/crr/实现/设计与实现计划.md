## 0. 一句话

被选中的内核函数在**编译期**被拆成「固定地址的跳板 + 可搬移的函数体」，所有既有
调用者不改地落到跳板上；**运行时**准备好新代码副本，阻断入口、等区域内执行流清空、
改写每函数一对**跳转桩**指令、放行，旧副本作废。索引更新量 = 函数个数，与调用点
数量无关。返回地址在栈上以**位置无关的返回标记 (k, Δ)** 存在，因此没有陈旧返回、
旧副本可整段去执行权限。

**当前进度：论文第 3 章的机制（方案甲）+ M3.opt 在 arm64 与 x86-64 **两个平台**都落地，
各通过 s1 与 S3 规模、单核与多核的冒烟与并发压力测试。M7（x86 移植）已完成。**

## 1. 当前状态（已做 / 已验证）

arm64（`s1-vfs` 37 函数）在 QEMU TCG 上冒烟 **PASS**：

- 启动到用户态运行 /init，全程 **0 崩溃**；
- 8 次用户态触发随机化全部成功（`rounds` 1→9，`rounds_missed`=0）；
- `/proc/ikaslr/layout` 前后对比 **layout changed = 1**（函数体确实被搬移）；
- `stale_fixups`=0（返回标记方案消除了陈旧返回）、`whitelist_rejects`=0；
- 机制被真实负载充分驱动（M3.opt 后单核一次冒烟：`enters`=`outs`=10638，
  `enter_backoffs`=0、`enter_forced`=0）。`enters`/`outs` 的口径已变，见 §2.4。
- **4 核（`SMP=4`）同样 PASS**：判空协议自测 `srcu_wrong`=0（全部运行与其局限见 §5）。
- **S3 规模（487 函数）+ 4 核 PASS**：冒烟 layout 变化、`stale_fixups`=0；并发压力
  （4 worker × 200 轮触发 + 持续 VFS 负载）180/200 轮成功、`whitelist_rejects`=0、
  `stale_fixup_fails`=0。s1 并发压力 200/200。（跑通 S3 修掉的三个真 bug 见 §3。）

**注意**：冒烟里的 `critical_path_ns`（~2.1 ms，其中 `cp_update_ns` 2.05 ms 是 TCG 下
逐桩 `text_poke`）**不是性能数据**——QEMU TCG 是解释执行。论文的常驻税/停顿窗口/
多核扩展性数字都要在**真机**上测；内联汇编计数版已就绪（§2.4），缺的只是平台。

编译期改造对 `CONFIG_IKASLR=n` 无影响（不加载 pass）。x86 仍是旧路径（target 槽 +
C 跳板），未随本轮改造，待 M7 移植。

## 2. 机制设计（以当前代码为准）

### 2.1 三段协作

```
编译期 (LLVM pass)            链接期                 运行时
tools/ikaslr/llvm/            scripts/ikaslr/        kernel/ikaslr/
IKaslrPass.cpp                gen_stubs.sh           core.c randomize.c tramp.S ...
```

### 2.2 编译期：LLVM pass（`tools/ikaslr/llvm/IKaslrPass.cpp`，arm64 路径）

对名单（`IKASLR_FUNCS` 指向的文件，每行一个函数名；下标即 **k**）里的每个函数 F：

1. **函数体位置无关化**：把体内所有指向区域外的引用改成**绝对地址物化**。
   arm64 用 `movn/movk/movk` 三条占位序列，立即数编译期留空（0），真实地址记入
   `.ikaslr_fixups` 段（`.long 1b-.` 偏移 + `.quad sym`，PIE 下走 `R_AARCH64_RELATIVE`）。
   这样函数体内**没有任何数据读取**（放弃了字面量池，为第 4 章观察点只执行铺路）。
2. **调用点改写为「标记—分支」序列**（体内每个 call）：
   ```
   adr  x30, 1f            ; 返回点
   adr  x16, F_body        ; 本函数体入口（PC 相对）
   sub  x30, x30, x16      ; x30 = Δ
   movk x30, #k, lsl #32   ; x30 = (k, Δ)，k=本函数下标
   <物化目标到 x16>; br x16 ; 目标 = 直接:fixed_out_G / 被随机化函数原名 / 间接:见下
   1:
   ```
   用 `br` 而非 `bl`——`bl` 会把真实返回地址写进 x30 落栈，正是标记要消除的泄露与
   陈旧返回来源。**所有跳出目标都必须绝对物化再 `br`**（PC 相对 `b` 在函数体搬移后
   指错，实测崩在变体地址−16.8MB）。
   - 直接调用外部函数 G → 目标 = `fixed_out_<G>`（每模块本地一份出口跳板）。
   - 直接调用被随机化函数 → 目标 = 其原名（即入口跳板）。
   - **间接调用** → 目标 = `__ikaslr_indirect_out`（thunk），运行期函数指针放 x16。
     不能像直接调用那样把标记放 x30 直接跳目标：间接目标可能是普通函数（末尾 `ret`），
     会 ret 到标记崩溃；thunk 用真实返回地址 `blr` 后再解析回体。
   - 参数按 AAPCS64 钉到 x0–x7，且**全部标为输入输出（in-out, tied）**：一次真调用会
     破坏参数寄存器，只标输入时 LLVM 会误以为它们在 asm 后仍存活（实测 putname(0xc)）。
3. **prefix data 重入序列**：`[3 x i32] = {0x10000070, 0x8b110210, 0xd61f0200}` 即
   `adr x16,.+12; add x16,x16,x17; br x16`，附在函数体入口前 12 字节，随体搬移。
   迁移单元因此从 `F_body−12` 起算。
4. **入口/出口跳板（汇编，方案甲：每函数/每目标一份）** 经 `M.appendModuleInlineAsm`
   发出，符号名 = 原函数名（外部调用者不改），落 `.tramp.text.<F>`。计数**内联**在
   跳板里（论文 §3.3.2 形态）：只用 x16/x17 与 x9/x10，不保存任何参数寄存器，栈上
   只压 16 字节（进入前的内外标志 + 返回地址/标记）。逐条模板见
   `kernel/ikaslr/tramp.S` 头注释，协议见 §2.4。
5. **`__ikaslr_body_<k>` 别名** 指向函数体（供链接期 `nm` 生成桩）。
6. **拒绝**：变参、naked、经栈传参（arm64 第 9+ 参 / 大结构体 byval）、体内含浮点/
   聚合参/sret/>8 参/musttail 调用点的函数——记入 `$O/ikaslr-skipped.txt`。

### 2.3 链接期：跳转桩区（`scripts/ikaslr/gen_stubs.sh` + lds + `link-vmlinux.sh`）

`link-vmlinux.sh` 在整体链接前用 `nm` 查出所有 `__ikaslr_body_<k>`，生成稠密桩表
`.tmp_ikaslr_stubs.o`（每桩 8 字节，缺失 k 填 `brk` 占位），每趟 `vmlinux_link` 带上。
第 k 个桩恰在 `__ikaslr_stubs + 8k`：
```
__ikaslr_stub_<k>:
    b __ikaslr_body_<k>       ; 入口桩：fixed_in 的 bl 落此 → 函数体入口
    b __ikaslr_body_<k> - 12  ; 重入桩：resolve_token 落此 → 函数体 prefix
```
随机化时改写这两条 `b` 的立即数即完成一个函数的 **O(1) 索引更新**（取代 target 槽）。
两条指令共 8 字节、按 8 字节对齐，运行时以**一次 64 位存储**同时替换（见 §2.4）。
lds 宏 `IKASLR_STUBS` 把 `.ikaslr.stubs` 紧邻 `.rand.text` 放置（同 128 MB 直接分支
量程内）。桩汇编须用 kallsyms 同款 flag（含 `KBUILD_AFLAGS_KERNEL`，否则 clang 按
host 架构汇编报 “invalid mnemonic 'b'”）。

### 2.4 运行时（`kernel/ikaslr/`）

- **早期物化补丁**（`core.c: ikaslr_apply_fixups`，`init/main.c` 在 `poking_init()` 后调）：
  遍历 `.ikaslr_fixups`，把函数体里 movn/movk 的空立即数补成 `.quad` 里的最终地址。
  物化的都是**固定对象**绝对地址（母本=变体），一次性早期补即可。**时机关键**：被
  随机化函数（VFS 等）在启动早期即被调用，远早于 `late_initcall`，故必须在
  `start_kernel` 里补，不能放 `ikaslr_init`。
- **从桩区反建函数表**（`core.c: ikaslr_build_table_stubs`）：反解每个桩入口 `b` 的
  目标得函数体，k=桩序号，迁移单元 = `[body−12, 下一单元起点)`（含 prefix）。
- **`resolve_token` + `__ikaslr_indirect_out`**（`tramp.S`，共享一份）：`resolve_token`
  由标记算出 `stub_base+8k+4`（重入桩）并 `br`，全程不读保存地址的内存；间接 thunk
  用真实返回地址 `blr` 目标、返回后 `b resolve_token`。
- **重随机化**（`randomize.c: ikaslr_rerandomize`）：阻断→等空→**改写桩**
  （`ikaslr_point_stubs`：入口桩→变体体入口 `base+off+12`、重入桩→prefix `base+off`）
  →放行→退役旧变体。变体准备（`ikaslr_prepare`）从 `body−12` 复制整个迁移单元。
- **改桩是整段批量写（2026-09-21）**：桩区连续、每函数 8 字节，所以
  - 每个变体的**整个桩区内容在 `ikaslr_prepare` 里预先编好**（`v->stub_img`，含缺失 k
    的 `brk` 占位——用常量填，不从桩区读回，为只执行保护留余地）；分支立即数编码与
    ±128 MB 量程检查因此都在阻断窗口**之外**，量程不够的变体不会变成 READY；
  - 窗口内只调 `aarch64_insn_write_u64s()`（新增于 `arch/arm64/kernel/patching.c`）：
    每页经 fixmap 映射一次、每函数一次 64 位存储、最后对整个桩区刷一次指令缓存；
    零分配、不睡眠，`patch_lock` 按页拿放。
  - 早先逐条调 `aarch64_insn_patch_text_nosync()`，每函数付两次「映射 + 撤销 + 刷
    指令缓存」，是阻断窗口的主要成分。**不保留常驻可写别名**（任意写威胁模型下等于
    把桩区交给攻击者），可写映射只在这次调用期间存在。
- **变体池**：4 个预分配变体，`module_alloc` 分配（落在跳转桩 ±128 MB 量程内；
  直接用 `MODULES_VADDR..MODULES_END` 会拿到模块区最低端、离映像 ~2 GB 越界）。
  状态机 FREE→READY→LIVE→RETIRED，后台工作队列补充，关键路径零分配。
- **执行流追踪（M3.opt，`track.c` + 跳板内联汇编，交接文档 §4.1）**：
  - **每任务内外标志** `thread_info.ikaslr_inside`。标志为 1 的进入是区域内部调用，
    不碰计数。**EL1 异常入口把标志存进 `pt_regs.unused2` 并清零、返回时恢复**
    （`entry.S` 的 `kernel_entry 1`/`kernel_exit 1`），中断处理程序的进出因此单独计数。
  - **每 CPU 一对只增不减的计数** `ikaslr_cnt[cpu].{enter,exit}`（64 字节对齐，跳板按
    `ikaslr_cnt + (cpu<<6)` 寻址）。跨边界进入 `enter++`、离开 `exit++`，被阻断的
    瞬态进入用再加一次 `exit` 撤销。随机化一侧：置阻断 → `smp_mb` → Σexit →
    `smp_mb` → Σenter，**先 exit 后 enter**，相等才算空（论证同 SRCU 的
    `srcu_readers_active_idx_check()`，写在 `track.c` 文件头）。
  - **跳板不关抢占**：计数用 `ldxr/stxr` 原子更新，取 CPU 号与加一之间被迁移也只是
    记到原来那个核上，求和不变（同 SRCU 的 NMI 安全读端）。顺序固定为「加一 →
    `dmb ish` → 置标志 → 查阻断」与「清标志 → `exit++`」，中断插在任何两步之间计数
    都只会偏大不会偏小。
  - **四处阻断检查共用一条慢路径** `__ikaslr_blocked_slow`（汇编保存 x0–x8 后调
    `ikaslr_blocked_slow()`）：撤销计数、等放行、重新进入。区域内部调用的进入/返回
    被拦时也是「减一等待、放行后加一」（论文形态；此刻执行流手里只有返回标记，
    可以被搬走）——取代了旧的「嵌套进入一律放行」。不可睡上下文自旋有上限，
    到限则带计数硬进入（`enter_forced`），随机化方据此超时跳过本轮。
  - 等空改为**轮询**（只增计数没有「归零」事件可挂唤醒）：短自旋后在可睡上下文
    `usleep_range(20,50)`——单核上必须睡，否则在区域内被抢占的任务永远跑不出来。
  - **`thread_info` 字段偏移怎么交给 pass 发出的汇编**：`tramp.S` 把
    `TSK_TI_IKASLR_INSIDE`/`TSK_TI_CPU` 定义成绝对符号 `__ikaslr_ti_inside`/
    `__ikaslr_ti_cpu`，跳板写 `ldr w17,[x16,:lo12:__ikaslr_ti_cpu]`，链接器把立即数
    填成偏移本身（BFD ld 已验证）。无需把 asm-offsets 传进 pass。
  - **统计口径变了**：`enters`=Σenter（入口跳板跨边界进入 + 出口跳板返回），
    `outs`=Σexit；区域内部调用不再计入。`active`=二者之差。热路径上不再有任何
    专门的统计指令，`IKASLR_STATS` 对 arm64 跳板已无影响。
  - **对照实现** `CONFIG_IKASLR_COUNT_GLOBAL`：所有核共用第 0 对计数（同一缓存行），
    供多核扩展性对比实验。顶层 Makefile 经环境变量 `IKASLR_COUNT_GLOBAL` 告知 pass。
  - x86 仍是 `core.c` 里的旧实现（全局原子 + `ikaslr_depth` + C 跳板），已用
    `#ifndef CONFIG_ARM64` 围起来，待 M7。
- `/proc/ikaslr/{stats,trigger,layout}`，以及 `CONFIG_IKASLR_TRACK_SELFTEST` 下的
  `track_selftest`（`control.c`）。

### 2.5 关键不变式

- 所有跨区域控制流必经跳板（编译器全覆盖重定向 + 构建期扫描断言）。
- 函数体内无任何指向区域外的 PC 相对引用（`scripts/ikaslr/verify_movable.py` 校验）。
- 栈上不存真实代码地址，只存返回标记（跨任意次随机化恒定）。
- 同一时刻只有一份可执行代码（无副本）。

## 3. 设计决策（已定）

**四个设计问题（作者 2026-09-20 拍板）：**
1. **经栈传参函数**：直接拒绝（arm64 9+ 参基本不存在）；变参在论文讨论里写“暂不处理”。
2. **`b fixed_out_G` 改绝对物化 + `br`**（论文 §3.3.2 清单同步改）。
3. **`pt_regs` 里也存返回标记**（异常入口/返回转换 pc、x30、x16、x17）——列为 M3.5。
4. **arm64 放弃字面量池，改 `movn/movk` 占位 + `.ikaslr_fixups` 修补表**（已落地）。
5. **平台顺序：先 arm64**。

**跳板结构：方案甲**（每函数 `fixed_in_F`、每目标 `fixed_out_G`，只有 `resolve_token`
共享）——按开销选：甲的 `fixed_in`→`stub` 是链接期编好的直接分支，热路径零地址物化，
与论文表 3-3 成本模型一致；乙（共享例程 + 寄存器传桩地址）每次多约 3 条指令、常驻税
+10~15%。甲的映像代价（S3 约 48 KB）可忽略。

**跑通 S3 规模修掉的三个真 bug（2026-09-21，都在 pass/早期启动，非并发问题）：**
1. **跨模块拒绝不一致**（曾崩在 token 值 `0x153_000000a8`）：被随机化函数体对
   「在名单里、但在它自己所在 TU 里被 pass 拒绝」的函数发 token+br，而 Kbuild 各 TU
   独立编译、调用方看不到被调方被拒，于是 br 到一个末尾是 `ret` 的普通函数、ret 到
   标记上。**改法**：每个随机化函数由**它的定义模块**导出 `__ikaslr_in_<k>`，调用点
   一律 token+br 到它——转换成功者是 `fixed_in` 的别名，被拒者是一段 `fixed_out` 式
   包装（正常 `bl` 原地函数、再 `resolve_token` 回去）。调用方无需知道被调方状态。
   S3 实测 12 个函数被拒（10 因函数体、2 因签名），全部经此路径。
2. **全局地址作参数未物化**（曾崩在变体区的错误锁地址 / 回调地址）：`&global` 作为
   调用参数时，`makeBodyPositionIndependent` 会「整条跳过内联汇编」，而标记序列本身
   就是内联汇编且在它之前生成——于是这类参数残留为 PC 相对 `adrp/add`，函数体一搬移
   就指错（`find_vm_area` 的 `spin_lock(&vmap_area_lock)`、`shrink_dcache_parent` 传给
   `d_walk` 的回调 `select_collect`）。**改法**：`rewriteCallSitesAArch64` 收集参数时，
   引用全局的常量参数先过 `rebuildAbs` 绝对物化，与函数体内其它全局引用一致。
3. **地址物化时机对 S3 太晚**（曾在控制台起来前崩在 `0xffff00000000ffff`）：movn/movk
   补丁原在 `start_kernel` 的 `poking_init()` 之后，但 S3 名单里 `memblock_reserve`
   在 `setup_arch()` 里就被调用，远早于此。**改法**：移到 `head.S` 的
   `__ikaslr_apply_fixups`（紧跟 `__relocate_kernel`，MMU 刚开、映像仍整体可写、
   仅 boot CPU 在跑），经 ID map 的 TTBR1 别名读写、`ic iallu` 收尾。

**M3.opt 中相对论文清单的三处偏离（2026-09-20，待作者确认是否同步改论文）：**
1. **出口跳板不做运行期白名单查询**。`fixed_out_G` 里是一条写死在只读固定区的
   `bl G`，目标无法在运行期被改到集合之外——直接调用的白名单**由构造保证**。
   论文表 3-3「出口：白名单查询 约 12 条指令/约 7 周期」这一行在当前实现里不存在；
   建议论文改述为「由构造保证，零运行期开销」。间接调用的目标合法性本来就不在
   静态白名单范围内（第 5 章）。`whitelist.c` 现在只剩统计用途。
2. **区域内返回路径多一条 `tbz x30,#63` 兜底**：若某条异常入口没经过 `entry.S` 的
   「存标志并清零」（SDEI、el1t 等），处理程序会带着继承来的标志 1、以真实返回地址
   调用 F；计数不受影响，只需别把真实地址当标记解析。
3. **原子加一用 `ldxr/stxr`（LL/SC）而非 LSE**，保证任何 ARMv8 都能跑。N2 支持 LSE，
   真机测常驻税时可以再给 pass 加一个发 `ldadd` 的选项做对比。

**冒烟中真机发现并修复的四处**（都已入代码）：
1. movn/movk 补丁时机必须在 `start_kernel` 早期（非 `late_initcall`）。
2. 调用点参数寄存器必须标 in-out（否则跨调用存活值被破坏，putname(0xc)）。
3. 间接调用经 `__ikaslr_indirect_out`，且 thunk 地址也须绝对物化再 `br`（PC 相对 `b`
   搬移后指错）。
4. 变体用 `module_alloc`（落在桩 128 MB 量程内）。

## 3.9 x86-64 移植（M7，2026-09-22）

x86-64 与 arm64 是**同一套方案甲**，差异只在「x86 返回地址在栈上、不在链接寄存器」：

- **返回标记 push 到栈上**（arm64 放 x30）。跳板窥探栈顶，用 bit63 区分真实返回地址
  （内核地址 0xffffffff8… bit63=1）与标记（bit63=0）：真实地址 `ret`，标记 `jmp resolve_token`。
  返回路径多一条 `cmpq $0,(%rsp); js` 兜底——继承了内外标志的中断处理程序若以真实
  返回地址进来，不会被当标记解析（arm64 是 `tbz x30,#63`）。
- **计数用单条 `incq %gs:ikaslr_{enter,exit}_cnt`**（真 percpu，一条指令即原子于本核中断，
  比 arm64 的 ldxr/stxr 还省）；进入侧加 `mfence` 补 x86 的 store-load 重排（对应 `dmb ish`）。
  存储在 track.c 里按 `#ifdef CONFIG_X86_64` 用 percpu 变量，arm64 仍用 cpu 索引数组，判空
  求和逻辑共用。
- **地址物化用 `movabs`**（R_X86_64_64，走正常 boot 期 KASLR 重定位）：**不需要** arm64
  那套 `.ikaslr_fixups` 表和 `head.S` 早期修补——arm64 踩的「物化时机太晚」bug 在 x86 不存在。
- **跳转桩 16 字节**：入口/重入各一条 `jmp rel32`（5 字节 + 3 字节 int3 补齐），量程 ±2GB。
  变体用 `module_alloc`（x86 模块区在内核文本 ±2GB 内，满足 rel32）。改桩用 `text_poke`
  整段写入（进程上下文，取 text_mutex）。prefix 13 字节：`lea F_body(%rip),%r11; add %rcx,%r11; jmp *%r11`。
- **共享汇编** `kernel/ikaslr/tramp_x86.S`：resolve_token、间接出口 thunk、阻断慢路径入口、
  `__ikaslr_ti_inside` 偏移绝对符号。每函数跳板由 pass 的 `transformX86` / `buildFixedInAsmX86`
  等发出。

**x86 独有的三处工程处理：**
1. **`relocs` 工具白名单**：`__ikaslr_ti_inside` 是常量偏移，跳板以 `sym(%reg)` 引用会生成
   R_X86_64_32S 绝对重定位，加进 `arch/x86/tools/relocs.c` 的 S_ABS 白名单（同 xen 那批）。
2. **随机化线程自阻塞豁免**（`track.c: ikaslr_rand_task`）：x86 `text_poke` 的改桩路径会调用
   被随机化的函数，而随机化线程持有 block，若它也在 blocked_slow 里等 unblock 就是**自我
   sleeping 死锁**（实测 S3 x86 全体挂死）。放行随机化线程自身是安全的——阻断窗口内 live 与
   ready 两份变体都可执行。arm64 的 fixmap 写桩器极小、不碰随机化函数，故不触发这条。
3. **`rip` 相对与内联候选**：调用点取函数体地址必须用 `${N:c}(%rip)` 强制 rip 相对
   （`${N:a}` 在 `-mcmodel=kernel` 下给绝对地址，导致 Δ 算成变体位移而崩）；fixed_out 的
   `call G` 是模块汇编、对编译器不可见，若 G 是内联器决定不内联的 static inline，需
   `ensureEmitted`（改内部链接 + compiler.used）强制落地，否则链接期 undefined。

**验证（QEMU，TCG + KVM）**：s1-vfs(35 函数) 与 S3(472 函数)，单核/4 核，冒烟与并发压力
（4 worker×200 轮）全部 PASS——rounds 正常增长、layout 变化、`srcu_wrong`=0、
`stale_fixup_fails`=0。判空自测在 x86 上同样 srcu 误判 0。

**x86 尚缺**（不影响当前正确性，列作后续）：
- 中断入口的内外标志保存/清零（arm64 在 entry.S 做了）。x86 暂未做——分析与压力实测都
  表明中断继承标志不破坏计数平衡（嵌套调用不计数、返回走 bit63 兜底），但严格性上仍应补。
- `text_poke` 会睡眠，故 x86 的随机化目前只在进程上下文触发；原子上下文的非睡眠改桩
  （类比 arm64 的 fixmap 写桩）待 M6 前补。
- x86 版跳板常驻税分项微基准（microbench_asm.S 目前是 arm64 汇编）。
