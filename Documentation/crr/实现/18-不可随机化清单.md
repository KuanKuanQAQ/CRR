# 不可随机化代码的完整清单

> 全树实测,x86-64 `defconfig`,Linux 6.8,clang 14。采集时间 2026-09-10。
> 逐类的**函数名全名单**在同目录 `不可随机化清单/` 下,由
> `scripts/ikaslr/gen_funcs.py --dump-excluded` 生成,可随内核配置重跑。
>
> 这份文档的用处:回答"哪些内核函数不能被随机化、为什么、还能不能解决"。
> 其中有几类**在 2026-09-10 这一轮里被解决了**,清单把"曾经不行、现在行了"与
> "现在仍然不行"分开列,不混为一谈。

## 0. 一句话

全树 **60 554** 个有实体的内核函数里:

| 口径 | 不可随机化 | 占比 |
|---|---:|---:|
| 2026-09-10 之前(旁表一律排除) | 10 083 | 16.7% |
| **现在** | **5 814** | **9.6%** |

**而且现在剩下的 5 814 个,排除理由只有一条:per-CPU 访问。**
其余曾经的六类要么被解决,要么被证明是误判。

## 1. 仍然不能随机化的

### 1.1 per-CPU 访问 —— 5 814 个,**不可解**

名单:[`不可随机化清单/per-CPU-gs.txt`](不可随机化清单/per-CPU-gs.txt)

```
add %gs:0x7e147668(%rip),%rax     # this_cpu_off
add %rax,%gs:0x7e15cd35(%rip)     # vm_event_states+0x208
```

x86-64 的 per-CPU 变量按 `%gs:<常量偏移>` 访问,而那个偏移在指令里是 **RIP 相对**的
立即数;arm64 用 `tpidr_el1` 加常量偏移,同理。这个偏移**必须是常量** —— 它是
per-CPU 区内的位置,不是一个可以物化成 64 位绝对地址的东西。

编译器插件改不了它:这些访问由 `this_cpu_*` / `__percpu` 访问器展开成**内联汇编**,
而插件整条跳过内联汇编(改了会破坏 `"i"` 之类的操作数约束,见
[`17-implementation-current.md`](17-implementation-current.md) §1.2)。

**这是本方法的固有边界,不是实现偷懒。** 占全部函数的 9.6%,占当前全部排除的 **100%**。

> 这一条正好支撑本文的设计立场:**方法本身允许不可随机化的函数存在**。
> 它们留在非随机化区域,其防护由第 4 章的泄漏检测与第 5 章的 PA 验证承担。
> E4-C 的三桶数据(桶 1 有 176 373 个稳定地址 gadget)说明这部分的防护是必要的。

### 1.2 变参函数 —— 150 个,**不可解**

名单:[`不可随机化清单/variadic.txt`](不可随机化清单/variadic.txt)

跳板要把收到的变参原样转给函数体,而 IR 层做不到:只能转发**具名**参数,变参部分
连同 x86-64 的 `%al`(向量寄存器计数)一起丢失。唯一能原样转发的是 `musttail call`,
但它要求其后紧跟 `ret`,而跳板在调用之后**必须**执行 `ikaslr_leave()`,两者不相容。

> 这一条是这轮才发现的,而且发现之前它是一个**静默的数据损坏**:随机化
> `seq_printf` 之后 `/proc/self/status` 读出垃圾,表现为 `vsnprintf` 的
> "field width too large" 与读野指针的缺页 —— 而**启动看起来是成功的**,
> 所以先前的干净启动记录没有发现它。现在 pass 主动拒绝并打印
> `ikaslr: skipping <fn>: variadic`。

典型成员:`seq_printf`、`netdev_err/info/warn/printk`、`dev_printk`、`logfc`、
`shrinker_alloc`、`__request_module`、各 `*_printk` 族。

### 1.3 内联汇编里对全局变量的原子位操作 —— 少数

```
lock btsq $0x0,0xdf8623(%rip)   # linkwatch_flags
lock bts  %rax,0xdf79e6(%rip)   # proto_inuse_idx
lock btr  %rax,0xdf764b(%rip)   # proto_inuse_idx
```

`test_and_set_bit()` 一类对**全局变量**的原子位操作,由内联汇编展开,操作数是
RIP 相对的内存引用。插件跳过内联汇编,因此这些引用留在函数体里,搬走即错。

实测在 S3 候选里只有 3 个(`linkwatch_fire_event`、`proto_register`、
`proto_unregister`)。**理论上可解**(把内联汇编的内存操作数换成绝对寻址),
但要逐条改内核里的位操作宏,代价与收益不成比例,当前不做。

### 1.4 `naked` 函数

没有编译器生成的序言/尾声,函数体就是一段裸汇编,既不能加跳板也谈不上位置无关改造。
pass 主动拒绝。内核里极少,x86_64 defconfig 的候选集里为 0。

### 1.5 `.static_call_sites` —— 本质不相容,但**本配置下为 0**

静态调用点写回代码的是指向**区域外**的 `call rel32`,偏移随函数位置而变 ——
与"函数体内不得有指向区域外的 PC 相对引用"直接冲突,**无解**。

但要如实说明:**x86_64 `defconfig` 链接出来的内核里根本没有 `.static_call_sites` 节**
(实测 `readelf -SW vmlinux` 无此节),因此这一类当前**排除 0 个函数**。
换成大量使用静态调用的配置(tracepoint 密集、`preempt=dynamic`)才会有实际影响。

## 2. 曾经不能、现在可以了的

这一节是这轮的主要成果。每一条都给出**为什么之前判它不行**与**现在怎么解决的**。

| 类别 | 曾排除 | 现状 | 解决办法 |
|---|---:|---|---|
| `__bug_table` | 1 702 | ✅ 可随机化 | 查表时把变体地址换算回映像地址(`report_bug`) |
| `.smp_locks` | 1 609 | ✅ 可随机化 | 启动时打在母本上,变体从母本复制,天然带着 |
| `__jump_table` | 641 | ✅ 可随机化 | 打母本 + READY 变体,再切换变体使其生效 |
| `.altinstructions` | 193 | ✅ 可随机化 | 同 `.smp_locks` |
| `__ex_table` | 132 | ✅ 可随机化 | 查表时换算地址(`search_exception_tables` + `fixup_exception`) |
| **`static_cpu_has()`** | (被误报) | ✅ 可随机化 | **修正检查器的假阳性**,见 §2.2 |
| `__mcount_loc`(ftrace) | (曾误判) | ✅ 可随机化 | **判断本身是错的**,见 §2.3 |

名单仍保留在 `不可随机化清单/` 下(`BUG-WARN-report_bug.txt` 等),
文件名即当年的排除理由,现在它们是**"已解决"的证据清单**而非排除清单。

### 2.1 地址键旁表:换算地址而不是改表

`__ex_table` / `__bug_table` 在链接期把"某条指令的地址"编码进表项,而表项位于固定
地址。函数体一搬走键就失配。**做法不是去改表,而是换算查表用的地址**:

```
查表前  ikaslr_live_to_image()   变体内地址 -> 映像链接期地址
查到后  ikaslr_image_to_live()   表给出的地址 -> 当前变体内地址
```

不改表是必须的:`__ex_table` 按地址排序、二分查找,每轮随机化重排几千条表项的代价
无法接受。细节见 [`17-implementation-current.md`](17-implementation-current.md) §3.7。

### 2.2 `static_cpu_has()` —— 检查器的假阳性,13 个函数被错误排除

`verify_movable.py` 曾把 13 个 vmalloc/页表族的函数报成不可搬移:

```
is_vmalloc_addr_body
    到区域外的直接调用/跳转: jmp ffffffff82b57148 <_einittext+0x2676>
```

那个目标在 **`.altinstr_aux`** 节里,是 `static_cpu_has()` 的辅助代码:

```
ffffffff82b57148: testb $0x1,-0xcc77d(%rip)   # boot_cpu_data+0x6a
ffffffff82b5714f: jne   ffffffff81ecca1d <is_vmalloc_addr_body+0x2d>
ffffffff82b57155: jmp   ffffffff81ecca30 <is_vmalloc_addr_body+0x40>
```

它测 CPU 特性后**跳回函数体内**。而那条跳出去的 `jmp` 在启动时会被
`apply_alternatives()` 换成 nop 或一条函数内部的跳转 —— 实测**这 13 个函数的
23 处跳出区域的 `jmp`,100% 被 `.altinstructions` 覆盖**。

变体是从映像母本复制的,复制发生在 alternatives 应用**之后**,所以变体里根本没有
那条 `jmp`。**检查器查的是启动前的映像,因此报了假阳性。**

决定性验证:把这 13 个单独随机化并跑并发压力测试 —— **3/3 干净启动,零 oops,
自测与压力全过**。

已修:`verify_movable.py` 现在读 `.altinstructions`,对被它覆盖的指令放行并单独计数。
S3 范围因此从 483 个函数恢复到 **496 个**(全部可搬移,3/3 干净)。

### 2.3 `__mcount_loc`(ftrace)—— 判断本身是错的

我起初把 ftrace 判成"与位置无关性本质冲突",并把含 `__mcount_loc` 的函数列进硬约束。
**实测推翻了这个判断**:`CONFIG_DYNAMIC_FTRACE` 在**构建期**就把 `call __fentry__`
换成了 5 字节 NOP,静态映像里根本没有那条 PC 相对调用 —— 开着 `FUNCTION_TRACER`
编 S3,`verify_movable.py` 依然报"全部可搬移"。

真正的冲突在**运行期启用 tracer 的那一刻**,而且表现是**静默失效**而非崩溃。
详见 [`实验/E3-C-与既有机制共存.md`](实验/E3-C-与既有机制共存.md)。

若按"含 `__mcount_loc` 就排除"处理,开着 ftrace 的内核**一个函数都不能随机化**
(53 281 个插桩点覆盖几乎全部函数),而代价只是一项功能损失 —— 收益与代价严重不对等。

## 3. 静态筛选之外:必须实测

`gen_funcs.py` 按重定位做静态启发式,**必然有漏网**。正确做法是以
`verify_movable.py` 为准迭代:

```
编一次 → 扫出不合格函数 → 从名单剔除 → 重编 → 直到为 0
```

S3 的实际迭代结果(取前 512 个候选):

| 阶段 | 剔除 | 原因 |
|---|---:|---|
| pass 主动跳过 | 7 | 变参(`seq_printf`、`netdev_*` 等) |
| `verify_movable` 实测 | 22 → **9** | 修正假阳性后只剩 9 个 |
| 　其中 per-CPU | 6 | `release_pages`、`kmem_cache_free_bulk` 等 |
| 　其中内联汇编位操作 | 3 | `linkwatch_fire_event`、`proto_register/unregister` |
| **最终 S3** | **496 个** | 全部可搬移,3/3 干净启动 |

**静态筛选漏掉 per-CPU 的原因**:这些访问是内联汇编展开的 RIP 相对引用,
在 `.o` 的重定位里不一定呈现为 `gen_funcs.py` 检查的那几种形态。因此
**实测这一步不能省**。

## 4. 复现

```sh
# 全树分类清单（现行口径）
python3 scripts/ikaslr/gen_funcs.py --build-dir <O=目录> \
    --scope '**/*.o' --refs '**/*.o' \
    --dump-excluded Documentation/crr/实现/不可随机化清单

# 对照：若旁表一律排除（即本轮之前的口径）
python3 scripts/ikaslr/gen_funcs.py ... --exclude-soft

# 变参函数（需 CONFIG_DEBUG_INFO_DWARF4 的内核 + pyelftools）
# 见本文件生成时用的 DWARF 枚举脚本

# 实测可搬移性
python3 scripts/ikaslr/verify_movable.py <vmlinux> --arch x86_64
```

## 5. 对正文的影响

1. §3.x / §6.3.2 引用"不可随机化比例"时用 **9.6%**,并说明**全部来自 per-CPU**。
   16.7% 那个数是旧口径,已作废。
2. **不要再写"ftrace 与本机制互斥"**(§2.3),也不要把 `__mcount_loc` 列为排除理由。
3. 变参函数是**新增的一类**,要写进不可随机化的分类里,并说明它此前是静默数据损坏。
4. `.static_call_sites` 要注明"本质不相容,但在评测配置下为 0 个函数" ——
   否则读者会以为它排除了很多。
5. §3.4.3 讲位置无关时可以用 `static_cpu_has()` 这个例子说明:**判定可搬移性必须
   考虑启动期的代码改写**,只看静态映像会误判。
