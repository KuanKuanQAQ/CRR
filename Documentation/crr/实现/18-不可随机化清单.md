# 哪些内核函数不能被随机化

> 全树实测,Linux 6.8,x86-64 `defconfig`,clang 14。采集时间 2026-09-10。
> 逐类的**函数名全名单**在同目录 `不可随机化清单/` 下,由
> `scripts/ikaslr/gen_funcs.py --dump-excluded` 生成,可随内核配置重跑。
>
> **本文自成一篇**,不需要先读别的文档 —— §0.2 把读懂它所需的机制背景交代清楚。

---

## 0. 前置

### 0.1 这份文档回答什么

I-KASLR 把一部分内建内核函数在运行期反复搬移。但**不是所有函数都能搬**。
本文回答三个问题:

1. 哪些函数不能被随机化,分别有多少个,名字是什么;
2. 为什么不能 —— 每一类的技术原因;
3. 哪些**曾经**被判为不能、现在已经可以了,以及当初为什么判错。

### 0.2 读懂本文需要的四个概念

**① 随机化区域与跳板。** 被选中的函数在编译期被拆成两半:

| 部分 | 落在哪 | 地址 |
|---|---|---|
| **跳板**(`fixed_in`) | `.tramp.text.<fn>`,保留原函数名 | **固定,永不搬移** |
| **函数体** | `.rand.text.<fn>`,改名为 `<fn>_body` | **会被搬移** |

所有既有调用者不用改动 —— 它们调用的是原函数名,而原函数名现在是跳板。
跳板做的事是:进入区域 → 经一个 `target` 槽间接跳到函数体 → 离开区域。
**每个函数只有一个 `target` 槽**,一次随机化只改写这些槽,与调用点数量无关。

**② 变体与母本。** 运行期预分配了 4 份**变体**(variant),每份是一块可执行缓冲区,
容纳全部函数体的一种排布(顺序打乱 + 随机间隙)。随机化就是把 `target` 槽从当前变体
指向下一个变体。

而**母本**指内核映像里原始的 `.rand.text`。**准备新变体时始终从母本复制**,
不从当前变体复制(以当前变体为源会与"退役变体填陷阱指令"的后台工作项竞态)。
母本在首次随机化后被置为不可执行,但它仍是所有变体内容的唯一源头 ——
**这一点在 §2 的几类解决办法里反复用到**。

**③ 可搬移的判据。** 函数体要能被整体搬到任意地址,就**不得含有指向区域外的
PC 相对引用**:

- x86-64:任何 `(%rip)` 寻址;任何目标落在区域外的 `call`/`jmp <绝对地址>`
- arm64:任何 `adrp`;任何目标落在区域外的 `bl`/`b`

函数**内部**的相对跳转随函数整体搬移自动保持正确,不必处理。
编译器插件的工作就是把对外引用改写成**绝对地址 + 间接转移**
(x86-64 用 `movabs`,arm64 用随函数搬移的字面量池)。

**④ 插件改不到的东西:内联汇编。** 插件整条跳过内联汇编 —— 改它会破坏
`"i"`(立即数)一类的操作数约束(实测改写 `WARN_ON` 的 `"i"(__FILE__)` 会直接编不过)。
**下面几类不可随机化的根源,基本都是内联汇编。**

## 2. 仍然不能随机化的

### 2.1 per-CPU 访问 —— 5 814 个,**不可解**

📄 [`不可随机化清单/per-CPU-gs.txt`](不可随机化清单/per-CPU-gs.txt)

```
add %gs:0x7e147668(%rip),%rax     # this_cpu_off
add %rax,%gs:0x7e15cd35(%rip)     # vm_event_states+0x208
```

x86-64 的 per-CPU 变量按 `%gs:<偏移>` 访问,而那个偏移在指令里是 **RIP 相对**的;
arm64 用 `tpidr_el1` 加常量偏移,同理。这个偏移**必须是常量** —— 它表示变量在
per-CPU 区内的位置,不是一个可以物化成 64 位绝对地址的东西。

这些访问由 `this_cpu_*` / `__percpu` 访问器展开成内联汇编,而插件跳过内联汇编
(§0.2 ④)。

**这是本方法的固有边界,不是实现偷懒。** 占全部函数的 9.6%,占当前全部排除的 **100%**。

> 这一条正好支撑本方法的设计立场:**允许不可随机化的函数存在**。它们留在非随机化
> 区域,其防护由泄漏检测(第 4 章)与 PA 验证(第 5 章)承担 —— 而不是靠"把所有
> 代码都随机化"。

### 2.2 变参函数 —— 150 个,**不可解**

📄 [`不可随机化清单/variadic.txt`](不可随机化清单/variadic.txt)

跳板要把收到的变参原样转给函数体,而在编译器 IR 层做不到:只能转发**具名**参数,
变参部分连同 x86-64 的 `%al`(向量寄存器计数)一起丢失。

唯一能原样转发全部参数的是 `musttail call`,但它要求其后**紧跟 `ret`**,
而跳板在调用之后**必须**执行"离开区域"的记账 —— 两者不相容。

> **这一条被发现之前是一个静默的数据损坏。** 随机化 `seq_printf` 之后,
> `seq_printf_body` 里的 `va_start` 读到的全是垃圾:`/proc/self/status` 读出乱码、
> `vsnprintf` 报 "field width too large"、以及读野指针的缺页。
> 而**启动看起来是成功的**,所以此前的干净启动记录没有发现它。
>
> 现在插件主动拒绝并打印 `ikaslr: skipping <fn>: variadic ...`,
> 构建脚本把这些名字收进 `$O/ikaslr-skipped.txt`。

典型成员:`seq_printf`、`netdev_err/info/warn/printk`、`dev_printk`、`logfc`、
`shrinker_alloc`、`__request_module`,以及各 `*_printk` 族。

### 2.3 内联汇编里对全局变量的原子位操作 —— 少数

```
lock btsq $0x0,0xdf8623(%rip)   # linkwatch_flags
lock bts  %rax,0xdf79e6(%rip)   # proto_inuse_idx
lock btr  %rax,0xdf764b(%rip)   # proto_inuse_idx
```

`test_and_set_bit()` 一类对**全局变量**的原子位操作,由内联汇编展开,
操作数是 RIP 相对的内存引用。插件跳过内联汇编,因此这些引用留在函数体里,搬走即错。

实测在 S3 候选(前 512 个高引用函数)里只有 3 个:`linkwatch_fire_event`、
`proto_register`、`proto_unregister`。

**理论上可解** —— 把这几处位操作宏的内存操作数改成绝对寻址即可。但要逐条改内核里的
位操作宏,代价与收益不成比例,**当前不做**。

### 2.4 `naked` 函数 —— 规则存在,但 x86 上没有实例

没有编译器生成的序言/尾声,函数体就是一段裸汇编,既不能加跳板也谈不上位置无关改造。
插件主动拒绝(`ikaslr: skipping <fn>: naked`)。

实测:`__naked` 在本树里 `arch/x86`、`kernel`、`mm`、`fs`、`net` **一处都没有**;
`include/linux/compiler_types.h` 的注释自己就写着 "currently the only user of
`__naked`" 是 ARM。因此这一类在 x86-64 上**排除 0 个函数**,规则是为 arm64 与将来
准备的。

### 2.5 `.static_call_sites` —— 本质不相容,但**本配置下为 0**

静态调用点在运行期被改写成指向**区域外**的 `call rel32`,偏移随函数位置而变 ——
与 §0.2 ③ 的判据直接冲突,**无解**。

但要如实说明:**x86_64 `defconfig` 链接出来的内核里根本没有 `.static_call_sites` 节**
(实测 `readelf -SW vmlinux` 无此节),因此这一类当前**排除 0 个函数**。
换成大量使用静态调用的配置(tracepoint 密集、`preempt=dynamic`)才会有实际影响。

**正文引用时必须注明这一点**,否则读者会以为它排除了很多函数。

## 3. 曾经不能、现在可以了的

| 类别 | 曾排除 | 现状 | 解决办法 |
|---|---:|---|---|
| `__bug_table` | 1 702 | ✅ | 查表时换算地址 |
| `.smp_locks` | 1 609 | ✅ | 启动时打在母本上,变体从母本复制 |
| `__jump_table` | 641 | ✅ | 打母本 + 未启用的变体,再切换变体使其生效 |
| `.altinstructions` | 193 | ✅ | 同 `.smp_locks` |
| `__ex_table` | 132 | ✅ | 查表时换算地址 |
| `static_cpu_has()` | (被误报) | ✅ | **修正检查器的假阳性**,见 §4.1 |
| `__mcount_loc`(ftrace) | (曾误判) | ✅ | **判断本身是错的**,见 §4.2 |

名单仍保留在 `不可随机化清单/` 下(文件名即当年的排除理由),
现在它们是**"已解决"的证据清单**而非排除清单。

### 3.1 地址键旁表:换算地址,而不是改表

`__ex_table`(异常修正)与 `__bug_table`(`BUG()`/`WARN()`)在链接期把"某条指令的
地址"编码进表项,而表项本身位于**固定地址**的只读数据段。函数体一搬走,键就失配 ——
本该被修正的异常会变成 oops,`WARN()` 会变成"不明陷阱"。

**做法不是去改表,而是换算查表用的地址**:

```
查表前   变体内地址  →  映像里的链接期地址
查到后   表给出的地址 →  当前变体内地址
```

不改表是必须的:`__ex_table` 是**按地址排序、二分查找**的,函数搬走之后排序就乱了,
每轮随机化重排几千条表项的代价完全无法接受。而换算只是两次线性查找,
且只在"地址确实落在当前变体里"时才发生 —— 普通异常只多两条比较。

### 3.2 启动时一次性施加的:母本自动覆盖

`.altinstructions`(CPU 特性相关的指令替换)与 `.smp_locks`(SMP 锁前缀)都是
**在启动时一次性**打在映像上的。而变体**始终从母本复制**(§0.2 ②),
复制发生在这些补丁应用之后,**所以变体天然带着已打好的补丁**,什么都不用做。

### 3.3 运行期改写代码的:静态键

`__jump_table`(静态键)的开关是**运行期**改写代码,因此要分两步:

**第一步:打映像母本 + 所有已就绪但尚未启用的变体。** 母本非打不可 —— 不打母本的话,
下一轮随机化时新变体从母本复制,这次开关就**悄无声息地退回旧状态,而且不报任何错**。

**第二步:当前正在执行的那一份,不去改它,而是换掉它** —— 触发一次随机化,
切到一个第一步已经打过补丁的变体上。

为什么不直接改当前那一份,两条路都走不通:

1. x86 的 `text_poke_bp()` **根本无法寻址变体** —— 它把待改写地址存成**相对
   `_stext` 的 s32 偏移**,而变体分配在 vmalloc 区、与 `_stext` 相距几十 TB,
   偏移直接溢出(实测拿到截断地址后缺页)。
2. 退而求其次的"阻断入口 + 等区域变空再直接改写",在大范围下等不到空
   (实测 483 个函数覆盖 VFS/mm/net),而等待期间整个区域被阻断,系统反而卡住。

换一份则同时绕开这两点:新变体是**从未被执行过的新内存**。

**静态键为什么与本方法相容**:它改写的那条 JMP,偏移是"目标标号 − 本指令",
两者同属一个函数、随函数整体搬移,差值不变。

## 4. 两处判错与更正

### 4.1 `static_cpu_has()` —— 检查器的假阳性,13 个函数被错误排除

可搬移性检查器 `verify_movable.py` 曾把 13 个 vmalloc / 页表族函数报成不可搬移:

```
is_vmalloc_addr_body
    到区域外的直接调用/跳转: jmp ffffffff82b57148 <_einittext+0x2676>
```

那个目标在 **`.altinstr_aux`** 节里,是 `static_cpu_has()` 的辅助代码:

```
ffffffff82b57148: testb $0x1,-0xcc77d(%rip)   # boot_cpu_data+0x6a
ffffffff82b5714f: jne   ffffffff81ecca1d <is_vmalloc_addr_body+0x2d>
ffffffff82b57155: jmp   ffffffff81ecca30 <is_vmalloc_addr_body+0x40>
```

它测完 CPU 特性后**跳回函数体内**。而那条跳出去的 `jmp` 在启动时会被
`apply_alternatives()` 换成 nop 或一条**函数内部**的跳转 —— 实测**这 13 个函数的
23 处跳出区域的 `jmp`,100% 被 `.altinstructions` 覆盖**。

而变体是在 alternatives 应用**之后**从母本复制的,**所以变体里根本没有那条 `jmp`**。
检查器查的是**启动前**的映像,因此报了假阳性。

**决定性验证**:把这 13 个函数单独随机化并跑并发压力测试 ——
**3/3 干净启动,零 oops,内核自测与压力测试全过。**

已修:检查器现在读 `.altinstructions`,对被它覆盖的指令放行并单独计数
(没装 `pyelftools` 时会明确警告"`static_cpu_has()` 一类会被误报")。
S3 范围因此从 483 个函数恢复到 **496 个**(全部可搬移,3/3 干净)。

> **给正文的一个具体例子**:判定可搬移性**必须考虑启动期的代码改写**,
> 只看静态映像会误判。

### 4.2 `__mcount_loc`(ftrace)—— 判断本身是错的

起初把 ftrace 判成"与位置无关性本质冲突",并把含 `__mcount_loc` 的函数列进硬约束。
**实测推翻了这个判断。**

`CONFIG_DYNAMIC_FTRACE` 在**构建期**就把 `call __fentry__` 换成了 5 字节 NOP:

```
ffffffff81f0f660 <dput_body>:
  f3 0f 1e fa       endbr64
  0f 1f 44 00 00    nopl 0x0(%rax,%rax,1)   ← ftrace 的补丁点，构建期就是 NOP
  55                push %rbp
```

静态映像里根本没有那条 PC 相对调用 —— 开着 `FUNCTION_TRACER` 编 S3 范围,
检查器依然报"全部可搬移"。

真正的冲突在**运行期启用 tracer 的那一刻**:`__mcount_loc` 共 53 281 条、
其中 477 条指向随机化区域,ftrace 按表里的**映像地址**打补丁,而首次随机化后映像的
`.rand.text` 已置为不可执行、再不执行 —— 补丁打在死代码上,**当前变体完全不受影响**。

也就是说表现是**静默失效**(启用 tracer 对被随机化的函数无效),而不是崩溃。
kprobes 是同一失效模式,且已实测:

| 探什么 | `register_kprobe` | 随机化前命中 | 随机化后命中 |
|---|---|---:|---:|
| 跳板 `ikaslr_st_add` | 成功 | 1 | 1 ✅ |
| 函数体 `ikaslr_st_add_body` | **成功** | **0** | **0** ❌ |

若按"含 `__mcount_loc` 就排除"处理,开着 ftrace 的内核**一个函数都不能随机化**
(插桩点覆盖几乎全部函数),而代价只是一项功能损失 —— **收益与代价严重不对等**。
因此不排除。

## 5. 静态筛选之外:必须实测

`gen_funcs.py` 按 `.o` 的重定位做静态启发式筛选,**必然有漏网**。
正确做法是以 `verify_movable.py` 为准迭代:

```
编一次 → 扫出不合格函数 → 从名单剔除 → 重编 → 直到为 0
```

S3 范围的实际迭代结果(取引用数前 512 个候选):

| 阶段 | 剔除 | 原因 |
|---|---:|---|
| 插件主动跳过 | 7 | 变参(`seq_printf`、`netdev_*` 等) |
| 检查器实测 | 22 → **9** | 修正 §4.1 的假阳性后只剩 9 个 |
| 　其中 per-CPU | 6 | `release_pages`、`kmem_cache_free_bulk`、`__xdp_return` 等 |
| 　其中内联汇编位操作 | 3 | `linkwatch_fire_event`、`proto_register/unregister` |
| **最终 S3** | **496 个** | 全部可搬移,3/3 干净启动 |

**静态筛选为什么会漏掉 per-CPU**:这些访问是内联汇编展开的 RIP 相对引用,
在 `.o` 的重定位里不一定呈现为筛选器检查的那几种形态。
**因此实测这一步不能省** —— 带着不可搬移的函数启动,一调用到就崩。

## 6. 复现

```sh
# 全树分类清单（现行口径）+ 逐类函数名全名单
python3 scripts/ikaslr/gen_funcs.py --build-dir <O=目录> \
    --scope '**/*.o' --refs '**/*.o' \
    --dump-excluded Documentation/crr/实现/不可随机化清单

# 对照：若地址键旁表一律排除（即 2026-09-10 之前的口径）
python3 scripts/ikaslr/gen_funcs.py ... --exclude-soft

# 实测可搬移性（判据见 §0.2 ③）
python3 scripts/ikaslr/verify_movable.py <vmlinux> --arch x86_64
```

变参函数名单由 DWARF 枚举得到(需 `CONFIG_DEBUG_INFO_DWARF4` 的内核 + `pyelftools`):
遍历 `DW_TAG_subprogram`,取带 `DW_TAG_unspecified_parameters` 子节点的。

## 7. 写进正文时的四条注意

1. 引用"不可随机化比例"用 **9.6%**,并说明**全部来自 per-CPU 访问**。
   16.7% 那个数是旧口径,已作废。
2. **不要写"ftrace 与本机制互斥"**(§4.2),也不要把 `__mcount_loc` 列为排除理由。
   准确的说法是:能共存,但被随机化的函数会失去可观测性,且表现是静默失效。
3. **变参函数是独立的一类**,要写进分类里,并说明它此前是一个静默的数据损坏 ——
   这比只列出"有这么一类"更有说服力。
4. `.static_call_sites` 要注明"本质不相容,但在评测配置下为 0 个函数",
   否则读者会以为它排除了很多。
