## 平台与关键决策（来自论文 R-61/R-64/R-67，已与作者确认）

- **两套物理机都有**：x86-64 一台、ARM64（支持 FEAT_PAuth + 调试观察点）一台。计划在**各自架构的 QEMU+KVM** 上跑功能与性能测试（因 KVM 不跨架构，故两台分别跑）。
- **主平台 = ARM**（第5章 PA、第4章观察点路径）；**x86 验证第3、4章可移植性**（第4章走 EPT 路径）。
- **LLVM pass 策略**：先做内核运行时，用现有「手工注解 + `.rand.text`/`.tramp.text` 段」路径实现（当下可编译可测），**LLVM pass 的职责写成明确接口 + 桩，留作后续步骤**。
- **待定项 D-EPT**：x86 下 EPT 施加 XOM 的部署模型（嵌套 EPT vs 宿主 KVM 侧强制）—— 见 [`04-detection.md`](./04-detection.md)，先把运行时写成平台无关。

### 稳健性复核（2026-09-09）
针对交接日志里"重随机化自测间歇失败 ~30%"重新核查当前 HEAD：用一次性压力测试
（在一个 boot 内采样约 2600 万次并发跳板调用 + 6.3 万次重随机化，覆盖 RDRAND / 回退
RNG / TCG 三种配置）+ 25/25 次纯净启动，**结果全部正确、零完整性失配**。结论：那些
失败日志来自更早的未修复状态（shuffle bug 修复之前），当前树是干净的。顺带修掉两处
真实缺陷（见提交 `ikaslr: fix latent variant-capacity overflow ...`）：
- **变体容量在极端情况下欠配**：`ikaslr_plan` 每函数多花 <16B 对齐填充，旧
  `ikaslr_var_capacity` 未计入；函数数超过约 PAGE_SIZE/16（实测 n=280 起）时最坏布局
  会越界写。3 个自测函数下不触发，但**编译器 pass 铺到真实子系统后是真的越界**。已改
  正公式，并加 WARN 兜底（越界即中止 prepare 而非踩内存）。
- 完整性自检**只打印 8 个比较字节里的前 4 个**，导致真实的第 5~8 字节失配显示成
  "want==got"的假象（都以 endbr64 开头）。已改为打印全部比较字节。

### ⚠ 不要重新加回的东西
评估用含漏洞模块（`evalvuln.c` 后门 + `init_attack.c`，原 S2.6）**已被作者要求永久移除**
（dual-use 攻击面代码，会阻塞模型安全审查）。检测机制的验证一律由**内核内自测**驱动
（受控 guest/内核代码读被保护页触发检测），**不要再实现任何提供内核任意读写的后门或
用户态攻击程序**。S2.6 在表中标记为"已移除"。
