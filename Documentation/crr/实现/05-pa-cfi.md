# 第 5 章实现细节：随机化辅助的 ARM PA 精准 CFI

> 对应论文第 5 章与 `PROGRESS.md` 的 Phase 3。设计依据见
> `../设计文档/草稿/毕业论文_第5章_v4.md`。**arm64 专属，需 FEAT_PAuth。**
> 本机用 QEMU TCG（`-cpu max`）功能验证；性能须真机。

## 核心思想（§5.1）

随机化区域内的控制流因目标地址不可预测而天然不可劫持，因此**进入随机化区域的
间接调用不需要 PA 验证**。把造成上下文传播的高扇入函数移入随机化区域，即可从
传播链中剪除它，链两侧的调用点得以各自建立唯一上下文。于是随机化与 CFI 互为条件。

## S3.1 PA 原语（已完成）

`kernel/ikaslr/pacfi.c`，`CONFIG_IKASLR_PACFI`（arm64 + ARM64_PTR_AUTH_KERNEL）。

用内核已安装的 APIA 密钥，配合我们自己的上下文：

```
sign(p, ctx) = PACIA p, ctx     认证是否通过：auth(sign(p,c),c) == p
auth(p, ctx) = AUTIA p, ctx      用错误 ctx 认证得到 != p
```

- 类型上下文 = 函数原型哈希（§5.5.1）；调用点上下文 = 调用点地址哈希。
- 显式 `pacia`/`autia` 需在 inline asm 里加 `.arch_extension pauth`（内核基础 -march
  不含 armv8.3；这条指令只**启用**扩展、不改限制，最自足）。

QEMU TCG 实测：签名在高位产生不同 PAC，roundtrip 通过，错误上下文被拒，
不同上下文签名互异。

```
probe: ptr=...16e4 sign(type)=3da1...16e4 sign(cs)=c0bf...16e4
probe: PASS - PAC works; roundtrip ok, wrong-context rejected, contexts distinct
```

## S3.2/S3.3 高扇入识别与渐进式精准化（已完成）

**运行时识别被多个调用点调用的函数（高扇入），无需全局静态分析。**

### ⚠ 论文 §5.4.2 的一处内部不自洽（需作者修订）

§5.4.2 的三阶段状态机描述："认证成功后以调用点地址重新签名并写回；另一调用点认证
失败后再以类型签名重试、成功即判高扇入"。**这一描述自相矛盾**：一旦 CS1 把指针重签
为 CS1 上下文并写回，CS2 既过不了自己的上下文、也过不了类型上下文（指针此刻是 CS1
签的，不是类型签的），因此 CS2 无法凭认证区分"CS1 已签（高扇入）"与"被篡改"——而
§5.4.2 恰恰要靠"类型重试成功"来区分。一个 PAC 指针同一时刻只能带一个上下文，鱼与
熊掌不可兼得。

### 本实现的自洽模型

- 存储中的指针**始终以类型上下文签名**（合法性真值来源，安全等价于 kCFI 基线）；
- 另用"归属"字段跟踪首个认领的调用点：首个 CS 认领；同一 CS 再来正常；**另一个 CS
  来 = 高扇入**；类型认证失败 = 篡改 = CFI violation。
- **精度（等价类 1）来自 S3.3 定稿**：识别稳定后，把单一归属的函数重签为其 owner 的
  调用点上下文，安全从类型级升到调用点唯一级；此后非 owner 触及也判高扇入。高扇入
  函数登记待迁入随机化区域（S3.5）、不再参与 PA。

这样既自洽、又达到论文的精度目标（单归属→唯一上下文，多归属→移入随机化区域）。
**建议 §5.4.2 据此改写**：不再声称"重签写回后仍能用类型重试判定"，而用"类型签名保持
不变 + 归属跟踪"来识别，精度由定稿阶段的重签提供。

### 验证（arm64 QEMU TCG）

```
ident: PASS - claim, high-fanin x2 (0->2), CFI violation (0->1), finalize+unique-context
```

即：单调用点认领后多次调用不误判；第二调用点触及判高扇入；篡改指针被 CFI 拒绝；
定稿把单归属函数升为调用点唯一上下文、之后非 owner 触及也判高扇入。

## S3.4 跳板处分区 PA 验证（已完成）

按控制流方向差异化：
- **进入随机化区域（fixed_in）：免 PA 验证**——区域内地址不可预测，篡改函数指针也
  无法指向特定 gadget，随机化已提供保护。这是开销下降的主要来源。
- **离开随机化区域（fixed_out）：强制 PA 验证 + 白名单**——目标在非随机化区域、
  地址已知固定。`ikaslr_pacfi_out()` 先以调用点唯一上下文认证目标，再查白名单
  （复用第 3 章），两者都过才放行。

**这同时防御 V4 的两种形态**：V4-A（非随机化区域内构造链）由该区域内间接转移的
PA 验证约束（S3.2 的等价类）；V4-B（劫持跨区域转移）由 fixed_out 的双重检查约束。

§5.6.3 的"PA 验证次数下降"直接由此而来：只有跨区域（fixed_out）的间接转移需要 PA，
进入随机化区域的一概免验；降幅 = 进入随机化区域的调用占全部间接调用的比例。

arm64 实测：`fixed_in 免验 10 次，fixed_out 验证 2 次（1 合法通过 + 1 篡改拒绝）`。

## S3.5 高扇入函数迁入随机化区域（已完成，逻辑层）

识别出的高扇入函数移入随机化区域后地址不可预测、天然不可劫持，**不再参与 PA
验证**——已由 `ikaslr_pacfi_verify()` 的 `high_fanin` 提前返回实现：传播链在此切断，
两侧调用点各自保有唯一上下文。物理迁移（区域内分配、复制函数体、生成跳板、纳入
变体池）**复用第 3 章随机化机制**；真实系统里由编译器为高扇入函数生成 fixed_in/
fixed_out（S3.1 的 pass 扩展）。`ikaslr_pacfi_migrate()` 提供逻辑登记。
