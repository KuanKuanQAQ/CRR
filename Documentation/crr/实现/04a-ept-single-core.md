# x86 EPT 路径为何仅限单核（论文 §4.5.1 / §4.6.1 需正面交代）

**本工作的 EPT 路径只在单核上实现与测量；多核覆盖由 ARM 观察点路径承担。**
这不是实现精力的取舍，而是因为**多核 EPT XOM 存在本质的设计难度**，而观察点机制
天然适配多核。下面给出理由，正文应据此如实说明范围。

## 多核 EPT XOM 的两个本质难点

### 难点一：XOM 的"临时开读"窗口是物理页级、全局的

第 4 章检测式 XOM 的核心动作是：代码页设为不可读，捕获读取后**临时开放读权限、
单步放行这一次合法读、再恢复不可读**（§4.4.3 检测源一）。

EPT 的权限作用在**物理页**上，而物理页是**所有 CPU 共享**的。因此当 CPU A 为了
放行自己的一次合法读（如 kprobes、ftrace）而把某代码页临时改为可读时，**这一页
对 CPU B 也同时变成可读**。攻击者在 B 上的读取正好可以趁这个窗口溜过去而不被
检测。单核下不存在"别的 CPU 趁机读"，多核下这是一个真实的检测盲窗。

要真正隔离，需要**每个 CPU 一套独立的 EPT 页表**（per-CPU EPTP），使 A 的临时
开读只影响 A 的视图。但 per-CPU EPT 会把 EPT 页表的内存与维护成本乘以核数，且
每次随机化导致的代码页迁移都要在每套 EPT 上分别更新——复杂度和开销都显著上升。

### 难点二：EPT 权限变更需要跨核 shootdown，且有一致性窗口

`INVEPT` 是**本地**指令：它只失效执行它的那个 CPU 的 EPT TLB。随机化迁移代码页、
或 XOM 权限变更时，必须给每个其他 CPU 发 IPI，让它们各自执行 `INVEPT`——即
"EPT TLB shootdown"，类比普通 TLB shootdown。

竞态在于：CPU A 改了某页的 EPT 权限并 `INVEPT` 了自己，但在 IPI 送达 CPU B 之前，
B 的 EPT TLB 仍缓存着旧权限，会用旧映射访问该页。对 XOM 而言，A 刚把一页设为
不可读，B 却还能读它，直到 shootdown 完成。随机化本已是跨核操作（变体切换 +
等待活跃集合清空），叠加 EPT 权限的跨核一致性后，同步链条进一步变长。

### 其余（非本质但真实）的工程成本

每个逻辑 CPU 要独立 `VMXON` + 维护自己的 VMCS + `VMLAUNCH`，并在 CPU 上下线、
电源状态切换（C-state、suspend/resume）时重新进入。这是"复制 + 生命周期管理"，
不改变机制，但是要正确处理的工程量。

## 观察点路径为何天然覆盖多核

AArch64 的硬件调试观察点是**每个 CPU 独立的调试寄存器**（`DBGWCR<n>_EL1` /
`DBGWVR<n>_EL1`）。多核下每个 CPU 各自编程自己的观察点，监控同一段地址区间：

- **天然隔离**：一个 CPU 的观察点触发、以及为放行合法读而临时关闭观察点，都只
  影响**本 CPU**，不像 EPT 那样改的是全局物理页权限。难点一的"全局开读窗口"不
  存在。
- **无 shootdown**：观察点是寄存器配置，不经 TLB，变更不需要跨核失效。难点二不
  存在。
- 代价只是"每 CPU 一份相同配置"，是复制而非新机制。

因此多核测量放在观察点路径上做，EPT 路径专注单核下的机制正确性与开销测量。

## 对论文的建议写法

在 §4.5.1 或 §4.6.1 明确：EPT 路径的实现与测量限于单核，原因是多核 EPT XOM 需要
per-CPU EPT 来消除物理页级临时开读的全局窗口、并承担 EPT TLB shootdown 的跨核
一致性成本；这两点在观察点机制下因其 per-CPU 特性而不出现，故多核评估由观察点
路径承担。**这恰好也是第 4 章"两条路径说明方法不绑定架构"论点的一个具体体现**：
不同硬件适合的部署形态不同。
