# I-KASLR 真机上手（arm64 原生构建 + 实测）

> 换到 arm64 真机上继续时先读这份。它把「原生 arm64 从零到跑出第一份真机数据」
> 的每一步写清楚，包括交叉编译换原生后的差异、已知的坑、以及第一批该跑的实验。
>
> 配套：机制全貌与设计决策见 `设计与实现计划.md`；投稿策略、数据硬规则、实验清单
> 见 `../DSN2027_投稿交接文档.md`。目前**所有性能数字都还没上真机**——这份文档要
> 产出的就是它们。
>
> 最后更新：2026-09-21。

---

## 0. 一句话

在 x86 上是**交叉编译** arm64（`CROSS_COMPILE=aarch64-linux-gnu-`）；在 arm64 真机上是
**原生编译**（去掉 `CROSS_COMPILE`），其余不变。跑起来后读 `/proc/ikaslr/microbench`
拿第一份真机常驻税数据。

---

## 1. 依赖

真机上需要：

- **clang**（编 LLVM pass 必需；内核也用它，因为跳板走 `-fpass-plugin`）。
- **LLVM 开发包**（编 pass 用，`llvm-config` + 头文件）。开发在 clang/LLVM 14 上做的；
  更高版本大概率也行，`tools/ikaslr/llvm/Makefile` 里 `LLVM_CONFIG` 可覆盖。
- 内核构建常规依赖：`make`、`bison`、`flex`、`libssl-dev`、`libelf-dev`、`bc`、`cpio`、
  `gzip`。
- 想在真机上先用 QEMU 冒烟（比反复重启真机快）：`qemu-system-aarch64`。arm64 宿主上
  QEMU 可以带 `-enable-kvm`，接近真机速度。

Debian/Ubuntu 一次装齐（按需调版本号）：

```bash
sudo apt install clang llvm-dev libclang-dev \
     build-essential bison flex libssl-dev libelf-dev bc cpio gzip \
     qemu-system-arm
```

确认 clang 能用：`clang --version`。

## 3. 编 LLVM pass（**每次换机器/换 clang 版本都要重编**）

pass 插件不在仓库产物里，也不随内核构建，必须单独编：

```bash
make -C tools/ikaslr/llvm
# 若 llvm-config 不在 PATH：
make -C tools/ikaslr/llvm LLVM_CONFIG=$(command -v llvm-config-16)
```

产物是 `tools/ikaslr/llvm/libIKaslrPass.so`。内核构建默认从这里找它
（`IKASLR_PASS` 可覆盖）。

---

## 4. 编内核（原生 arm64）

与交叉编译**只差一个 `CROSS_COMPILE`**（原生不需要）：

```bash
# O= 必须是绝对路径。zsh 不展开 O=~/ika 里的 ~，会在源码树下建出一个名为 ~ 的目录。
O=$HOME/ika

# 首次生成配置（原生 defconfig）
make -j"$(nproc)" O="$O" ARCH=arm64 CC=clang defconfig

# 打开 I-KASLR 相关开关（见 §5）后再编 Image
make -j"$(nproc)" O="$O" ARCH=arm64 CC=clang \
     CRR_TRAMPOLINE=y IKASLR_FUNCS="$PWD/scripts/ikaslr/funcs/s1-vfs.txt" \
     Image modules
```

交叉编译（在 x86 上，作对照）只是多一个前缀：

```bash
make -j"$(nproc)" O="$O" ARCH=arm64 CC=clang CROSS_COMPILE=aarch64-linux-gnu- \
     CRR_TRAMPOLINE=y IKASLR_FUNCS="$PWD/scripts/ikaslr/funcs/s1-vfs.txt" Image
```

**要点：**
- `CRR_TRAMPOLINE=y` 才注入跳板；`=n` 是对照组基线（什么都不随机化）。
- `IKASLR_FUNCS` 指向随机化名单，**必须绝对路径**。可选名单在
  `scripts/ikaslr/funcs/`：`s1-vfs.txt`（37 函数起步）、`s2-storage.txt`（128）、
  `s3-full.txt`（构建出 487 个可随机化函数体，默认范围）。
- 改了名单或重编了 pass，内核会**全量重建**（`IKASLR_STAMP` 把两者的哈希折进编译
  命令行，避免混用旧对象）。这是有意的，别觉得慢是出错。
- `CONFIG_IKASLR=n` 时 pass 不加载，对内核无任何影响。

## 5. 关键 config

在 `$O/.config` 里确认/打开（`./scripts/config --file "$O/.config" --enable X`
改完后 `make O="$O" ARCH=arm64 olddefconfig`）：

| 选项 | 值 | 说明 |
| --- | --- | --- |
| `CONFIG_IKASLR` | y | 机制本体 |
| `CONFIG_IKASLR_STATS` | y | `/proc/ikaslr/stats` 计数。**测常驻税时它对 arm64 跳板已无影响**（统计不再在热路径），可留着 |
| `CONFIG_IKASLR_MICROBENCH` | y | `/proc/ikaslr/microbench`，真机取数的主力 |
| `CONFIG_IKASLR_TRACK_SELFTEST` | y | `/proc/ikaslr/track_selftest`，判空协议自测 |
| `CONFIG_IKASLR_COUNT_GLOBAL` | n（默认）/ y（对照） | y 时所有核共用一对计数，供多核扩展性对比。**切换要全量重编**（pass 据此发不同序列） |
| `CONFIG_ARM64_BTI` | n | 位置无关改造制造的间接转移与 BTI 落地点标记结构性互斥；基线也须关，保证可比 |
| `CONFIG_SHADOW_CALL_STACK` | n | 跳板 clobber x18 |

## 6. 跑起来

### 6a. QEMU 冒烟（最快的正确性验证）

```bash
# 单核
./scripts/ikaslr/boot-arm64-smoke.sh "$HOME/ika"
# 多核（per-CPU 计数、判空自测、多核扩展性都要多核才有意义）
SMP=4 ./scripts/ikaslr/boot-arm64-smoke.sh "$HOME/ika"
```

脚本用 `tools/ikaslr/init_smoke.c` 造 initramfs，启动、读 `/proc/ikaslr`、触发随机化、
对比布局，并跑一次判空自测与微基准冒烟。判据：`SMOKE: PASS`、`srcu_wrong=0`、
`stale_fixups=0`。

并发压力（更狠，走嵌套/竞态/兜底）：把 initramfs 的 init 换成
`tools/ikaslr/init_stress.c`（4 worker × 200 轮触发 + 持续 VFS 负载），判据
`STRESS: PASS`、`whitelist_rejects=0`、`stale_fixup_fails=0`。

> QEMU TCG 是解释执行，**性能数字全部无意义**，只验证正确性。arm64 宿主上加
> `-enable-kvm` 会快很多，但要拿论文数据仍应在**真机裸跑**。

### 6b. 真机裸跑

把 `$O/arch/arm64/boot/Image`（+ `modules`）装到目标机、更新 bootloader 启动它。
起来后：

```bash
cat /proc/ikaslr/stats            # 区域边界、函数数、计数、随机化轮数
cat /proc/ikaslr/layout           # 各函数当前地址（root only；等于泄露随机化结果）
echo 1 > /proc/ikaslr/trigger     # 手动触发一次重随机化
```

## 7. 第一批实验（这台机器的价值所在）

### 7.1 跳板常驻税分项微基准 —— **先跑这个**

```bash
echo "2000000 11" > /proc/ikaslr/microbench   # iters batches，可选，默认 100000 9
cat /proc/ikaslr/microbench > microbench.csv
```

输出两组，对照着读（每次调用的纳秒 + PMU 周期/指令/分支预测失败）：

- **seq 组**：分项指令序列循环——`flag_rw` / `blocked_check` / `dmb_ish` /
  `count_llsc` / `count_lse` / `enter_seq`（完整进入序列）/ `enter_seq_nodmb`
  （去掉屏障）。量的是序列本身的下界。
- **call 组**：经真实跳板调用相对普通调用的**差值**（`delta_*` 列）——`leaf`（入口
  跨边界往返）、`out`（+出口跳板+标记解析）、`in`（+区域内部调用）、`ind`（+间接
  出口 thunk）、`poly`（标记解析的间接分支面对多目标时的预测表现）。

这份数据直接回答「常驻税花在哪」：**计数**贵还是**按标记返回的间接分支**贵。
交接文档 §7 的优化方向（比如把 `dmb` 挪到随机化一侧、LSE 换 LL/SC）据此决定。
`# pmu: yes` 才有周期数；`no` 说明这台机器 PMU 没开（真机一般有）。
`# lse_available: 1` 说明支持 LSE，`count_lse` 行才有数。

### 7.2 多核扩展性曲线

同一负载在 1/8/32/64 核下，`CONFIG_IKASLR_COUNT_GLOBAL` 开与关各编一份内核，
两条曲线画一张图——直接证明 per-CPU 计数相对全局共享计数的价值（交接文档 §4.1）。
负载建议 will-it-scale 的系统调用类用例或 netperf TCP_RR 多实例。

### 7.3 端到端开销（交接文档 §6 硬门槛）

四档配置：基线（`CRR_TRAMPOLINE=n`）、默认范围全激活（s3-full 483 函数）、
全内核候选未激活、全内核候选+触发。跑 LMBench、内核编译、fio、netperf、
wrk-nginx、SPEC CPU。**实测 CSV 不要带 `.predicted` 后缀，文件头写平台、内核配置、
日期、运行次数。**

### 7.4 稳定性

72 小时 stress-ng + LTP 循环，报告零崩溃与累计随机化次数。DSN 是可靠性会议，
成本低、加分多。

## 8. 已知的坑

- `O=` 用绝对路径（见 §4）。
- 换 clang 版本或改名单后 pass/内核要重编（§3、§4）。
- 判空自测（`track_selftest`）在 QEMU 上造不出朴素方案的误判（迁移耗时 ≫ 扫描间隔），
  真机多核才有意义；即便如此它也只是「没发现误判」，正确性靠 `track.c` 的论证。
- x86 仍是旧路径（全局原子 + C 跳板），本轮 arm64 改造未动它，待 M7。
