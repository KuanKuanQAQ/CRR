## 1. 目的

机械验证「**编译产物中不存在绕过跳板的跨区域控制流转移**」。清单称这是
**全文唯一一条可以被完全验证的安全性质**，第 2.7 节的不变式 I1 与 I3 都以它为前提，
投入产出比最高。

## 2. 配置

```
内核    ：Linux 6.8，x86_64_defconfig
开关    ：CONFIG_IKASLR=y、IKASLR_DEBUG=y、IKASLR_STATS=n
        关闭 RETPOLINE/RETHUNK/CPU_UNRET_ENTRY/CALL_DEPTH_TRACKING
        （randfuncs.c 用 -mcmodel=large，与 retpoline thunk 互斥）
随机化区域：0xffffffff81d91000–0xffffffff81d9107e（126 B，3 个示例函数）
跳板区域  ：0xffffffff81d90000–0xffffffff81d90099
```

## 3. 步骤

```sh
make O=<b> CRR_TRAMPOLINE=n x86_64_defconfig
scripts/config --file <b>/.config -e IKASLR -e IKASLR_DEBUG -d IKASLR_STATS \
  -d RETPOLINE -d RETHUNK -d CPU_UNRET_ENTRY -d CALL_DEPTH_TRACKING
make O=<b> CRR_TRAMPOLINE=n olddefconfig
make O=<b> CRR_TRAMPOLINE=n -j$(nproc) vmlinux
python3 scripts/ikaslr/scan_xregion.py <b>/vmlinux
```

扫描器全量反汇编 `vmlinux`，对每条控制流转移指令判定源/目标所属区域
（`rand` / `tramp` / `other`），凡「一端在 rand、另一端不在 rand」即为跨区域；
合法当且仅当另一端是跳板区。

### 区域内 3 处间接转移的人工核对

扫描器无法静态定间接转移的目标，单列复核。逐条反汇编 `ikaslr_rf_general_body`
并解析目标符号：

| 地址 | 指令 | 目标符号 | 角色 |
| --- | --- | --- | --- |
| `…105f` | `call *%rax` | `ikaslr_out_enter` | 声明目标 + 白名单检查 |
| `…1063` | `call *%rbx` | `ikaslr_rf_helper` | 真正的外部调用 |
| `…1071` | `call *%rax` | `ikaslr_out_leave` | 离开区域 |

三条正是设计中的 `fixed_out` 协议。同一函数里 `%r12 = ikaslr_rf_counter`
（经 `movabs` 绝对寻址），印证 §3.4.3 的 x86 方案。

## 6. 关键发现：扫描器有一个**漏报** bug（比结果本身重要）

首次运行报告「发现 1 处绕过跳板的直接跨区域转移」：

```
0xffffffff81d91016: jle ffffffff81d9101e <ikaslr_st_mul_body+0xe>  [rand→other @ 0xe]
```

但源 `…1016` 与目标 `…101e` **都在区域 `[…1000, …107e)` 内**，不该判为越界。根因：

```python
TARGET = re.compile(r"\b0x([0-9a-f]+)\b")     # 旧：只匹配带 0x 的十六进制
```

x86 的 objdump 把**分支目标印成裸十六进制**（`jle  ffffffff81d9101e <sym+0xe>`），
而**符号偏移才带 `0x`**（`+0xe`）。于是它一直抓的是**符号偏移**当目标。后果两面：

- **假阳性**：区域内分支被判成越界（上面这条）；
- **假阴性（更严重）**：外部代码跳进随机化区域时，`dst` 永远解析不成 `rand`，
  **真正的违规会被漏报**——而漏报正是这条安全性质最不能承受的方向。

已改为要求至少 6 位十六进制并取首个匹配（内核地址 16 位）。**修正后才得到上面的结果。**

## 8. 真实规模复测（S3：488 个函数，99.6 KB）

编译器 pass 生效后以 S3 范围重跑：

```
扫描的控制流转移指令总数      : 836,016
  其中直接转移                : 814,295
  其中间接转移                :  21,721
跨随机化边界的（直接）转移    : 0
  未经跳板（应为 0）          : 0
随机化区域内的间接转移（复核）: 1,722
```

**直接跨区域转移仍为 0**——不变式 I1 在真实规模下依然成立，且这次的样本是
488 个真实内核函数而非 3 个示例函数，结论强度大幅提升。

### ⚠ 但复核那 1 722 处间接转移，发现一个实现与设计的落差

把每条 `call *%reg` 回溯到紧邻的 `movabs $imm,%reg` 并解析目标符号，得到分布：

| 目标 | 数量 |
| --- | ---: |
| **走 `fixed_out` 协议**（`ikaslr_out_enter`／`ikaslr_out_leave`） | **2** |
| **直接调用外部函数** | **1 681** |
| 合计 | 1 683 |

直接调用的目标按频次：`kfree`(62)、`memset`(55)、`_raw_spin_unlock`(49)、
`_printk`(47)、`_raw_spin_lock`(39)、`mutex_unlock`(33)、`memcpy`(22)……
都是真正的外部内核函数。

那 **2** 处走 `fixed_out` 的来自**手工标注**的 `ikaslr_rf_general`
（它用 `IKASLR_OUT_CALL` 写成），而**编译器 pass 生成的 1 681 处都不经过 `fixed_out`**
——位置无关改造只是把 `call rel32` 变成了「绝对地址 + 间接调用」
（见 `../16-position-independence.md`）。

而 §3.4.3「优化一」要求：**随机化代码对外部函数的调用一律改由 `fixed_out` 处理**，
由它做白名单检查（第 3 章）与 PA 验证（第 5 章）。

旁证：本次 `/proc/ikaslr/stats` 显示 **`whitelist_entries = 2`**——488 个函数、
1 722 处外部调用，白名单里却只有 2 项（那 2 项来自手工标注的示例函数）。
**说明编译器 pass 既没有把外部调用路由到 `fixed_out`，也没有生成白名单。**

**后果**：
- 不变式 I1 的**出方向**（随机化区域 → 非随机化区域）当前**未被跳板约束**；
- 第 5 章的 `fixed_out` PA 验证对这些调用不生效；
- 性能上，当前数字**低估**了真实开销（少了每次外部调用的白名单查询）。

**这是下一个该做的实现项**：pass 应把外部调用改写成
`ikaslr_out_enter(target); (*target)(...); ikaslr_out_leave();`
（即手工标注里 `IKASLR_OUT_CALL` 的形式），并把目标登记进白名单。

> 在此之前，正文**不能**声称"所有跨区域转移都经跳板"——
> 目前成立的是"**没有绕过跳板的直接转移**"，出方向的间接转移尚未纳入。

## 9. 局限

- 扫描器不覆盖手写汇编与运行时生成的代码（见 §7）。
- 出方向的间接转移目前只能人工复核（§8），需等 pass 补上 `fixed_out` 路由后才能
  自动判定。
