## 共同前置

**几乎所有未完成的性能实验都卡在同一件事**：随机化区域里必须真有被随机化的内核函数。
本次已把 LLVM pass 与构建系统打通（见 [Pass 落地](E-pass-bringup-LLVM插桩落地.md)），
内核能编、能启动、自测通过，但**一调用到被随机化的函数就崩**——根因是
**pass 只做了跳板，没做函数体的位置无关改造**（§3.4.3），函数体里仍是
`call rel32` 一类 PC 相对引用，一搬就错。

因此剩余前置为：

1. **在 pass 里实现函数体位置无关改造**（外部调用经 `fixed_out`、全局变量改绝对寻址）
   ——这是真正的阻塞项；
2. 把 `libIKaslrPass.so` 与 `IKASLR_FUNCS` 加进构建依赖（现在改名单不会触发重编）；
3. **ORC**：被搬移函数的 ORC 表项须一并搬移，否则栈回溯失效；
4. 定下 **E3-10／R-67**（与 ftrace/kprobes 互斥还是共存）——它决定所有性能实验的配置。
