## 当前进度与下一步

**已不再是阻塞项**(2026-09-10 全部打通,见 [`../17-implementation-current.md`](../17-implementation-current.md)):
编译器 pass、函数级位置无关、`fixed_out` 与白名单、地址键旁表、阻断协议的嵌套自我阻塞。
S3(483 函数)在 4 并发 VFS 负载下随机化成功率 99–100%,零 oops。

**下一步顺序**(按清单第 7 章"建议顺序"的第一批,去掉需要 ARM 真机的):

1. **E3 的模型交叉验证** —— `init_tput.c` 做 Base vs +R 直接吞吐 A/B。
   E3-A 的模型预测纯系统调用负载下常驻税占单核 57%,这个量级必须端到端证实或推翻。
2. **E5-1** CFI 精度收紧口径(一次回填三处)。
3. **E4-C** 三桶 gadget 划分(工具已就绪)。
4. **E3-1** 索引收敛扩到 S3 规模,按类型分列。
5. **E4-D** 内存开销按当前名单复测。

**需要作者拍板的**:
- 若吞吐 A/B 证实 G ≈ 3400 万次/秒 的量级,极端系统调用负载下开销远超个位数。
  正文该报"典型负载个位数 + 极端负载 N 倍 + G 的分布",还是把 `+R` 档范围收窄?
  这影响 E3/E6/E7 的配置。
- **R-67**(与 ftrace/kprobes 共存):ftrace 一半已有答案(本质冲突),kprobes 待定。
