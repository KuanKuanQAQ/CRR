# E4-C　攻击者可用 gadget 的残余集合(三桶)

> 对应 `设计文档/草稿/实验总清单.md` §第2章 E4-C(论文 §4.6.6,W-46)。
> **本项在 v2 里被重新设计过**,原 E4-7 的口径是错的,见 §1。
>
> 工具:`scripts/ikaslr/gadget_census.py --buckets`(本次为它新增分桶能力)。
> 映像:`+R` 生产配置(`IKASLR=y`、`STATS=n`、`DEBUG=n`),范围 S3(480 个函数);
> 对照映像:`Base`(`IKASLR=n`)。ROPgadget v7.7,Linux 6.8,x86-64。
> 原始扫描结果 108 万 / 103 万条,见 `scripts/ikaslr/perf/results/`。

## 1. 原口径错在哪

原 E4-7 只统计"静态可得多少、随机化后可得多少",隐含假设是**随机化区域内的代码
攻击者用不了**。这个假设不成立:`fixed_in` 跳板位于**固定地址**,知道跳板地址就能
经它调用区域内的函数。因此残余攻击面不等于"非随机化区的静态计数"。

重新设计后按**地址是否稳定**与**可用粒度**分三桶。

## 2. 结果

区域边界(实测):

| 区域 | 范围 | 大小 |
|---|---|---:|
| 非随机化代码段 | `[0xffffffff81000000, 0xffffffff82200000)` | 18 874 368 B |
| 跳板区 `.tramp.text` | `[0xffffffff81eb0000, 0xffffffff81eb7013)` | 28 691 B |
| 随机化区 `.rand.text` | `[0xffffffff81eb8000, 0xffffffff81edef8f)` | 159 631 B |

### 三桶

| 桶 | 内容 | 地址稳定 | 可用粒度 | 可利用 gadget |
|---:|---|---|---|---:|
| **1** | 非随机化区域 | 稳定 | 任意 mid-function gadget | **176 373** |
| **2** | 跳板区域自身 | 稳定 | 任意 mid-function gadget | **918** |
| **3** | 经跳板可达的区域代码 | **入口**稳定 | **仅函数入口**(整函数复用) | **480** |
| — | (桶 3 区域内的 mid-function gadget,攻击者**用不到**) | 不稳定 | — | 3 953 |
| — | (落在可执行代码段之外,ROPgadget 把数据当代码扫出来的,非本实验对象) | — | — | 77 505 |

- **桶 2 密度**:918 / 480 = **1.91 个 gadget/跳板**(跳板区 28 691 B,60 B/跳板)。
  跳板体短且形式单一,但数量要如实数 —— 它是本方案**自己引入**的稳定地址代码。
- **桶 3 中的危险整函数入口:0 个**。检查清单里的 `commit_creds`、
  `prepare_kernel_cred`、`call_usermodehelper`、`set_memory_x` 等均不在 S3 范围内。
  **这取决于范围选取,换范围必须重测。**

### 最要紧的一个数

可执行代码段内的可利用 gadget 共 **181 244** 个(176 373 + 918 + 3 953),
其中因随机化而**地址不再稳定**的只有 **3 953 个,占 2.2%**。

> **随机化 480 个函数,只把 2.2% 的 ROP 可用 gadget 从稳定地址上移走。**

### 仅凭稳定地址(桶 1 + 桶 2,共 177 291 个)能拼出什么

| 原语 | 有无 | 处数 |
|---|---|---:|
| `pop rdi`(装参数 1) | 有 | 252 |
| `pop rsi`(装参数 2) | 有 | 1 689 |
| `pop rdx`(装参数 3) | 有 | 145 |
| `pop rax`(装系统调用号) | 有 | 368 |
| 任意内存写 | 有 | 24 832 |
| 任意内存读 | 有 | 2 079 |
| 间接调用/跳转 | 有 | 72 908 |
| 返回用户态(`swapgs`/`iretq`/`sysretq`) | 有 | 8 |

> 计数口径:判据放宽到"链子里实际用得上"的形态(容忍前后多几条指令),
> 但**不做副作用分析**,因此这些数字是**上界**,回答的是"有没有"而不是
> "有几条好用的"。

**结论:仅凭稳定地址就足以构造完整的 ROP 链。** 全部必需原语都在桶 1 + 桶 2 里。

## 3. 判据核对与诚实声明

清单要求本实验"不声称随机化后攻击者无 gadget 可用",而要报告残余集合有多大、
粒度是什么、以及它为什么不足以构成完整攻击链 —— **或者,如果足以,第 5 章的 PA
验证在其上施加了什么额外约束**。

实测落在**后一种情况**:

1. 残余集合 177 291 个稳定地址 gadget,**足以构成完整攻击链**;
2. 随机化本身只移走了 2.2%;
3. 因此**本方案的价值不在"减少 gadget 数量"**,而在于:
   - 把**被针对的那部分代码**的地址变成不可预测(桶 3 的 480 个函数);
   - 桶 3 只暴露**函数入口**,对应 return-to-libc 式的整函数复用,**不是 ROP**;
   - 非随机化部分(桶 1)的防护由第 4 章的泄漏检测与第 5 章的 PA 验证承担。

**这正好印证了"允许不可随机化的函数存在"这一设计立场**:不可随机的部分不是缺陷,
它的存在恰恰论证了对非随机部分施加额外防护的必要性(见
`../14-code-model-and-unmovable.md` 的口径说明)。

## 4. 与第 5 章的接口(清单点名要正面回答的)

桶 3 的可达性正是第 5 章 `fixed_in` 免验策略的攻击面:`fixed_in` 不做 PA 验证,
理由是"区域内地址不可预测"。**但经跳板调用的是函数入口,而入口地址恰恰是可预测的
(跳板地址固定)。**

因此 §5.7.3 要正面写:免验的安全性依据是**攻击者无法指向区域内任意位置**,
而不是无法指向函数入口;**整函数复用由白名单与第 4 章的审计承担**。

本次实测给这条论证补上了定量支撑:
- 桶 3 入口 480 个,其中危险整函数 **0** 个(当前范围);
- 白名单在 S3 下有 498 条(去重后),`whitelist_rejects` 在压力测试中恒为 0。

## 5. 复现

```sh
ROPgadget --binary <vmlinux> > gadgets.txt        # 全映像扫描，很慢
python3 scripts/ikaslr/gadget_census.py <vmlinux> --gadgets gadgets.txt --buckets
```

## 6. 对正文的影响

1. §4.6.6 要改写成三桶口径,**并明确说明仅凭稳定地址即可构成完整链**。
   把"随机化后攻击者可用 gadget 大幅减少"这类说法删掉 —— 实测只减少 2.2%。
2. **跳板本身引入 918 个稳定地址 gadget**(1.91 个/跳板),这是本方案的成本之一,
   §3.8 要求如实报告,不能略过。
3. §5.7.3 按 §4 的说法补上 `fixed_in` 免验的正确论证。
4. 引用 gadget 计数时必须写明"可利用"口径,并说明 ROPgadget 的 76% 噪声。
