# E3-2　跳板机制的微观开销

| | |
| --- | --- |
| **清单编号** | E3-2（第3章）；【W-34】 |
| **对应正文** | §3.6.3 |
| **状态** | 🟡 **玩具规模**（每次调用的 ns 值有效；"跨区域调用占比"待真实范围） |
| **接口** | `/proc/ikaslr/bench`（需 `CONFIG_IKASLR_DEBUG`） |

## 1. 目的

给出经跳板的跨区域调用相对直接调用的额外周期数，并**拆开**成三部分，说明代价花在哪里。

## 2. 微基准设计

`bench.c` 内置四档，各 200 000 次：

| 档 | 内容 |
| --- | --- |
| A | 直接调用等价函数 |
| B | 经 `target` 槽间接调用，但**不计数** |
| C | 完整 `fixed_in`（间接调用 + 进出计数） |
| D | 单次白名单查询 |

- 间接转移开销 = B − A
- **进出计数开销 = C − B**

## 3. 配置

```
CONFIG_IKASLR=y、IKASLR_DEBUG=y、IKASLR_STATS=n（生产档）
QEMU + KVM，-cpu host，4 vCPU，Xeon Gold 6448Y
```

## 4. 结果

| 项 | 实测 |
| --- | ---: |
| A 直接调用 | 5 ns |
| B 经 target 槽间接调用 | 7 ns |
| **C 完整 `fixed_in`** | **107 ns** |
| D 白名单查询 | 11 ns |
| 间接转移开销 = B−A | **2 ns** |
| **进出计数开销 = C−B** | **100 ns** |
| 跳板合计（C−A） | **102 ns** |

对照（清单记录的 `IKASLR_STATS=y` 档）：间接 2 ns / 计数 130 ns / 合计 133 ns。

## 5. 判据核对

| 判据（清单） | 结果 |
| --- | --- |
| 结论方向必须是「开销在计数而非间接转移」 | ✅ 100 ns vs 2 ns，计数占 **98%** |

> **一条必须写进正文的澄清**：本次 `IKASLR_STATS=n`，所以这 100 ns **不是统计计数器**，
> 而是**活跃执行流集合追踪本身**（自旋锁 + 数组扫描）。§3.6.3 若只报「跳板开销」总数
> 而不拆分，会把优化方向指错——**该优化的是计数结构**。
> 真机多核下这里有锁竞争，实际只会**比本次 4 vCPU 测得的更差**。

## 6. 仍缺：跨区域调用在真实负载中的占比（W-34）

微观开销 × 占比才是实际影响。

- **静态占比已测**：范围内 **61.2%** 的调用站点是跨区域的（15 020/24 549，
  见 `../12-got-codemodel-results.md` §4.3）。可作上界参照。
- **动态占比未测**：需真机 `perf` 在 LMBench/fio/netperf 负载下采样。
  本机无 `perf`，且 QEMU 下不具代表性。

> **做一次用两处**：该占比同时是 §5.6.3「PA 验证次数减少」论断的依据（R-53）。

### 一条与第 5 章咬合的观察

静态统计显示，**最热的跨区域目标全是极廉价、极高频的原语**：
`_raw_spin_unlock`(1 122 站点)、`_raw_spin_lock`(773)、`__rcu_read_unlock`(751)、
`preempt_schedule_notrace`(527)。它们本身只有几纳秒，若每次调用都付 102 ns，
相对开销约 **20 倍**。

但 `_raw_spin_lock` 被 773 个站点调用，**正是典型的高扇入函数**——按 §5.4.2 会被识别并
**迁入随机化区域**，此后调用变成区域内调用、不再经 `fixed_out`。
**因此第 5 章的高扇入迁移不只是 CFI 精度手段，更是第 3 章开销的关键缓解。**
建议把这层跨章耦合补进 §3.6.3 与 §5.4.2。

## 7. 坑（清单已列，本次复核）

1. **微基准会被编译器优化掉**。首次实现时基线档 200 000 次只花 119 ns，
   因被测函数是纯函数、参数为常量、结果未使用，循环被整个删除。
   现已用 `volatile` 输入并写回结果形成真实数据依赖。**做任何微基准前先自查这条。**
2. `wake_up()` 曾是最大单项（224→133 ns），已改为 `wq_has_sleeper()` 判断后再唤醒；
   本次复测确认该优化仍在。

## 8. 局限

当前随机化区域只有 3 个示例函数。**每次调用的 ns 值与范围无关**（它测的是单次跳板往返），
因此 102 ns 可用；但"实际影响 = 102 ns × 占比"里的占比必须用真实范围+真实负载测。
